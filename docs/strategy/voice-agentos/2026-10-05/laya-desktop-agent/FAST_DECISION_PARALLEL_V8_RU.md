# Fast Decision + Parallel Automation V8

The local app remains the product. Chrome is only a hidden browser-capability layer.

## Objective
Maximize **verified useful progress per unit latency, compute and human attention**.

## Decision loop
Goal → concurrent Library/browser/Windows prefetch → compact DecisionState → Laya System-1 → deterministic fastest-verified admission → durable H2/H1/H0 → effect/read → independent evidence → replan.

## Fast-path rules
1. Reuse a qualified registered capability by default.
2. Gather cheap exact evidence before paying for System-2 when evidence is missing.
3. Safe exact-bound READ_NAV UI actions may win when they unlock context.
4. System-2 is for novel reasoning/design/code.
5. High-unlock capability gaps become reusable-tool work.
6. WAIT/STOP are control states and are never utility-overridden.

## Real parallelism
Already supported:
- Library/browser/Windows decision prefetch runs concurrently.
- BrowserWatch and life-context ingestion run in background.
- Campaign DAG nodes use resource leases.
- Repo/tests/System-2 can run without owning foreground browser.
- H1 exposes disjoint-resource parallel lane plans.

### Same Chrome while the user works
Independent tabs/read/research lanes may run while the user works in the same installed Chrome/profile. The same mutable tab/composer is never written by two owners simultaneously. Trusted human input creates a foreground lease; AgentOS yields, keeps the mission durable and resumes after the quiet window.

## Reliable text/context capture
The old One Click Context failure mode was virtualized chats: the DOM may expose only part of history. Current stack uses streamed scroll traversal, role-marked and role-less/recycled message detection, explicit coverage/gaps/order, frame supplements, attachment inventory, large local TXT + metadata JSON + raw JSONL archives, BrowserWatch dedup and Windows UIA fallback. Full archives stay in canonical Library; model working packets remain bounded.
