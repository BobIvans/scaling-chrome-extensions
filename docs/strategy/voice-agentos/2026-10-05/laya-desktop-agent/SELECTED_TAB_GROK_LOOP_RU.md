# Selected tab → Grok/Grok Build → evidence → next action loop

## Goal

The user chooses the exact AI tab once in the local app. The system may observe/send only through the persisted binding and must revalidate it before every effect.

## State machine

### S0 DISCOVER_TARGETS
Extension/CDP adapter lists eligible tabs. UI shows title/origin/provider guess but does not treat guesses as identity.

### S1 BIND
User selects a tab. Runtime observes:
- browser profile/session;
- window/tab/target handle;
- origin;
- provider mode;
- account/workspace;
- conversation/chat/build session;
- branch/workspace when observable;
- adapter/selector contract digest;
- epoch.

Persist immutable TargetBinding revision.

### S2 OBSERVE
Read-only capture verifies current identity, DOM contract, latest messages and whether user is editing/typing. No send permission is implied.

### S3 BUILD_MISSION_STATE
Combine user goal + acceptance + pinned repo snapshot + selected context pack + previous receipts/results. Store state digest.

### S4 LAYA_ROUTE
Run only typed questions from `LAYA_QUESTIONS_CATALOG.json`. Laya output is DATA_ONLY. Deterministic policy maps the answer to one registered workflow or ABSTAIN.

### S5 PLAN_PREVIEW
Compiler resolves all critical slots: repo, destination binding, packet ID, mode, criteria, refs. Unknown capability becomes a Development Request.

### S6 EFFECT_INTENT
For external/browser effect:
- acquire writer lease + monotonic fence;
- ensure STOP not active;
- re-observe exact target identity;
- ensure user has not taken over composer;
- persist EffectIntent + nonce before action.

### S7 SEND_ONCE
Prepare exact draft, verify drafted text/hash where possible, invoke one send. Never immediately retry after timeout/ack loss.

### S8 RECONCILE
Observe exact outgoing prompt/nonce/message evidence. Result is VERIFIED / CONFLICT / EFFECT_UNKNOWN. UNKNOWN blocks blind retry.

### S9 READ_RESPONSE
Read terminal/partial response and bind it to exact conversation/request/attempt.

### S10 IMPORT_AS_CLAIM
AI output is stored as DATA_ONLY claim with provider/target/request hashes.

### S11 NEXT_DECISION
Laya classifies response:
- answer/analysis;
- needs context;
- code/change proposal;
- registered tool/action proposal;
- completion claim;
- blocker;
- ambiguous.

Policy chooses verifier, more context, coding task, registered action, follow-up AI question, or STOP/BLOCK.

### S12 FEEDBACK_DOC
Compile a bounded feedback document:
goal, current revision, actions attempted, evidence, verifier results, errors, open gaps, next questions and only relevant source parts. Feed it back to the same binding or an alternate explicitly selected target.

Loop until acceptance is directly verified, operator stops, attempt budget ends, or a blocking UNKNOWN occurs.

## Grok Build transports

### WEB_SELECTED_TAB
Keep for the user's visible current conversation/session. Uses current browser binding contracts.

### HEADLESS_GROK_BUILD
Registered coding transport invokes the installed Grok Build CLI in a pinned working directory with structured input/output and a process receipt. No arbitrary command string generated by Laya.

### ACP_GROK_BUILD
Preferred future app integration when ACP support is qualified. Reuses the same Intent/Packet/Result contracts.

Transport is selectable; memory/authority stays in Voice AgentOS.

## Required fault corpus

Tab closes/reuses ID; account switches; conversation switches; branch changes; user types during prepare; selector contract changes; browser restart; process crash after click; ack lost; duplicate response text; two writer attempts; STOP during send/wait; Laya low confidence; malicious webpage text asks for grant expansion; AI claims DONE without verifier evidence.
