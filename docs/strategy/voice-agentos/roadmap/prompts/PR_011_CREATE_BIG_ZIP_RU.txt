LAYA4-005 — Квалифицировать статический JS/TS parser и resolver
- ADR сравнивает parser candidates по JS/TS/JSX/TSX, offline packaging, Windows memory, pins и лицензии; package выбран по измерению.
- Parser извлекает symbols/ranges и imports; resolver поддерживает явно перечисленные ESM/CommonJS/relative/workspace/alias правила.
- Computed imports, unsupported exports, dynamic require и runtime injection представлены unresolved, не guessed exact edges.
- Ни import scanned module, ни install scripts, ни repository hooks во время анализа не запускаются.
- Размеченный corpus достигает предложенного precision gate LX4-03; recall и неподдерживаемые формы публикуются отдельно.
LAYA4-006 — Объединить Python и JS/TS связи в provenance graph
- Edge хранит type, source range/hash, parser/resolver version и evidence class.
- Python static, JS/TS static, declared contract и heuristic candidate не смешиваются в один unqualified relation.
- Unresolved/dynamic/ambiguous links доступны в graph query и packet gaps.
- Graph построен детерминированно из pinned snapshot; SCC не зависит от directory enumeration order.
- Rebuild на одинаковых inputs даёт одинаковый graph digest; цикл не вызывает unbounded traversal.
LAYA4-007 — Связать owners, tests, contracts и capability candidates
- Name heuristic, declared mapping и observed test coverage имеют разные relation types.
- Тесты/контракты разрешаются только внутри выбранного snapshot/scope; внешний missing contract остаётся gap.
- У registration/API/schema adapters есть owner mapping, уменьшающий риск изменения только одной стороны интерфейса.
- Capability candidate из parser не получает статус enabled/installed; для него показано missing qualification.
- UI позволяет открыть источник связи и явно включить tests/contracts в packet.
LAYA4-008 — Планировать связанные группы и bounded chunks
- MVP работает с текущим Python graph и честно отмечает JS/TS gaps; новый resolver не блокирует первый release.
- SCC рассматривается как logical group; oversized SCC делится на bounded parts с neighbour references.
- Каждый group имеет reason/owner/source refs; эвристики явно отмечены.
- Raw byte coverage проверяется отдельно от повторных explanatory snippets в нескольких docs.
- Порядок и IDs детерминированы snapshot/planner version; добавление несвязанного файла не перенумеровывает все logical source IDs.
