1. SHARED IDENTITIES И VERSIONING
Namespace/project/source/source_revision/snapshot/task/criteria/packet/projection/attempt/operation имеют разные IDs. Logical retry сохраняет operation_id; новый пользовательский intent получает новый. Same ID + другой canonical payload => IDEMPOTENCY_CONFLICT до mutation. packet revision immutable: изменение goal, selection, criteria, source bytes или transform создаёт новую revision. destination profile и projection digest привязаны отдельно от provider-neutral packet. Сохранять source ref с SHA256 raw bytes и exact [start,end) offsets. Derived UTF-8 spans не называются raw offsets; хранить mapping. Timestamp capture отличается от validity interval.

Предлагаемые JSON schemas — contracts v1. Подписывать/хэшировать domain envelopes по выбранной canonicalization; RFC 8785 — proposed choice после cross-language vectors. Не считать обычный sort_keys эквивалентом JCS. Digest domain включает schema name/version и immutable content; сам digest и mutable receipt не включаются. Blob hash считает исходные bytes. Package MANIFEST использует обычные SHA256 файлов и не является wire serialization proof.

2. WS-013 — PACKET/RESULT/NEED_CONTEXT
Публичный compiler принимает GoalRef, критерии, snapshot, selection query/ranges и export profile. Сначала resolve + pin revisions, затем policy filter, coverage/missing ledger, deterministic order, projected parts. Selected обязательный источник, не помещающийся в transport budget, остаётся next-part ledger. Unknown provider limits имеют UNKNOWN; byte limit, tokenizer-exact token count и estimate method — отдельные поля. Budget управляет part/frame/window, число sources/parts не имеет скрытого общего cap.

Записывать корзину через owner; removal создаёт selection revision. WHY_THIS_PACKET содержит criterion/goal/user reason и origin. Private sources не выдают названия/метаданные в external projection без разрешённого metadata scope. Сначала redaction по explicit protected fields + policy, затем heuristic scan как дополнительный сигнал. Raw bytes неизменны. Redaction map остаётся локальным restricted metadata; external index перечисляет разрешённые ranges/omissions и не содержит removed text. Preview открывает уже материализованный immutable projection; export переносит те же bytes и сверяет projection digest. При смене account/chat/scope/bytes old readiness invalidated.

Multipart export переиспользует PR-003 owner: staged publication, hashes, offline index, checked resume. Если provider отклоняет часть, создаётся новая transfer projection с child subranges и supersedes, нейтральный source остаётся тем же. Не редактировать существующие immutable parts. Resume local export не создаёт внешнюю delivery attempt. Ручной экспорт первым обеспечивает roundtrip без UI automation; provider APIs/UI квалифицируются downstream.

Result ingest сначала сохраняет raw bytes и hash; затем strict schema/binding validation: task, packet/projection, criteria revision, request/session/target где применимо. Missing fields/unknown IDs/старый snapshot => UNBOUND или STALE в review. Claimed citation разрешается только в captured immutable source; criterion evidence проверяется отдельно. DONE и exit code не равны achieved. Imported executable, SQL, permit, env или commands остаются данными, не подключаются к dispatch. При corrupted duplicate payload same result ID => conflict, а не overwrite.

NEED_CONTEXT содержит manifest-owned source/part ID, revision, offsets, criterion и reason. Host не открывает filesystem path из текста. Validate range integer/nonnegative/end>start/end<=object length; validate namespace/snapshot/projection visibility. Outside-scope не раскрывает наличие другого private source. Matching repeated request возвращает тот же delta artifact; send attempt создаётся только явным transport effect. SOURCE_DRIFT предлагает новую packet revision, не подменяет старый range новой строкой. Library gateway предоставляет typed search/read_span/status; jobs.propose только создаёт bounded proposal через существующий owner.

3. WS-014 — BACKUP/RESTORE/RETENTION/SYNC
Подробный алгоритм в docs/DATA_RECOVERY_RU.txt. Реализовать manifest-reachable objects и coordinated generation. DB snapshot сам по себе не защищает GC внешних blobs: pin objects от manifest enumeration до complete publication. Events должны соответствовать snapshot watermark. В verified backup хранить portable references и schema/build compatibility, без credential material, исполняемых grants и переносимой внешней отправки. Job/task history сохраняется, execution fences при restore меняются, неизвестный эффект остаётся UNKNOWN.

Restore — staging каталог; byte/hash/integrity/relationships/counts/heads/overlays/tombstones check; текущий delete overlay; dry-run migration на копии; один writer quiescence; атомарное переключение active descriptor с recovery journal. Старый backup с отсутствующим current deletion ledger не может silently стать current: открыть отдельный recovery namespace. Sync — portable immutable artifacts + events с origin ID; merge conflict record, dedup replay; живой SQLite не делить. MVP local portable sync без облака обязателен как tested service при enabled option, сеть/crypto provider только отдельная qualification.

4. WS-015 — TEMPORAL RETRIEVAL
Расширить базовый поиск PR-010: namespace/project/export scope до snippets/ranking; exact source/version/path/quote, FTS candidates, graph neighbours bounded, optional rerank. Deterministic tie-break score -> temporal applicability -> stable source revision/range. Текущий запрос и as_of время выбирают effective revision; superseded source остаётся историей. Conflict set содержит обе версии, причины и статус correction. Corrections — append-only event с provenance; после restart и restore не исчезают. Deleted source исключён из current views, historical recovery только явно.

Почему выбран: exact/FTS/filter/graph/manual/summary, distance и scope. Summary имеет source refs и stale state; при source drift он не остаётся verified. Unknown fact создаёт missing category/request с expected criterion benefit. Selected refs, excluded reasons, uncovered required ranges, projected bytes и token method видны. Query может сканировать corpus странично без global source cap; bounded result не означает полный архив прочитан AI.

Frozen relevance corpus: независимые expected exact refs до запуска, hard negatives, same phrase/different project, old correction/new rule, conflicting opinions, Unicode/CRLF, tombstone, nonexistent quote. Считать recall@k, correct-version rate, citation validity, cross-scope leakage, explicit missing accuracy; отдельно cold/warm latency и peak RSS с числом rows/versions/bytes. Не выбирать pass threshold после получения результата; предложенные targets утверждаются measurement owner до замера.

5. WS-016 — INSTALLED WINDOWS CLIENT
PR-008 Tk/stdio — исходный pilot, не выбор окончательного shell. Сравнить продолжение Tk и доступный альтернативный shell на одной Windows build: install footprint, cold boot, RAM, keyboard/UIA support, crash/reconnect, range preview. Решение записать ADR с actual versions, measured receipts и причинами. Если ни один кандидат не проходит accessibility/install criteria, оставить DEC5-01 OPEN и targeted next action. Не менять owner ради framework.

Per-user installer поставляет shell и sidecar/backend с установленной версией; app data root вне transient install directory, bootstrap без cwd dependency. First-run показывает data path, build, namespace, backend status. Установщик не создаёт вторую library при обнаруженном legacy profile. Upgrade schema только через coordinator и rehearsal; signed/release provenance статус честный. Autoupdater/canary — PR-018. Uninstall shell сохраняет корпус по default и закрывает собственные processes, не убивает чужой Core.

IPC reuse typed transport dispatch. Handshake -> protocol/schema/build/profile/store generation; negotiation rejecting unknown command/oversize/mismatch до mutation. Stdout — protocol frames, diagnostic log/stderr redacted. Frame parser incremental length+UTF-8; page budgets согласовать с actual pilot, большие outputs через job/artifact refs. No arbitrary executable/argv/env/SQL endpoint. Responses fenced by connection generation/request IDs; late old response не меняет new UI. Canonical write command -> durable intent transaction -> Core queue/job; ack loss -> lookup original operation_id, не новое намерение.

UI virtualization: cursor на стабильный snapshot + query revision; bulk selection handle без загрузки всех rows; end-of-file preview через range API. Search/source versions/why/packet/backup/capabilities/task recovery панели имеют text states и keyboard actions. Неподдержанный operation отображается GAP с владельцем; нельзя сделать enabled Run по catalog title. Screen reader accessible name/role/state/error; focus возвращается на trigger после dialog, stop не скрыт behind modal. Private corpus не включать в distribution/demo fixtures.

6. WS-017 — CAPABILITIES/TEMPLATES/GRANTS/STOP
Registry хранит candidate description и registered entrypoint отдельно. Qualified capability binding: ID/version, installed build digest, adapter digest, input/output schema, effects, resource envelope, required credential refs, verifier digest/environment/cases. State PLANNED/UNKNOWN/QUALIFIED/STALE != enabled. Enabled вычисляется по installed match + current qualification + policy grant + dependencies. Schema/effect/build/adapter/grant drift инвалидирует зависимый receipt, а не все unrelated checks.

Templates operator-registered: известный adapter/entrypoint, named typed slots, repo alias/namespace, allowed path roots, tool version, cwd policy, resources, verifier/recovery. Imported doc не задаёт executable/argv/env. Shell metacharacters — обычные данные в validated slot либо deny, subprocess shell=false; Windows quoting/path verification квалифицируются. Navigation VS Code — version-aware mapped source, pinned URI/view при drift, Unicode/spaces сохраняются. Без editor dependency MISSING_DEPENDENCY; не запускать downloaded script для discovery. Credential ref разрешается только execution adapter в границах grant, secret bytes не сохраняются в corpus/frame/log/export.

Grant/profile живёт у текущего policy owner. Trusted operator changes, canonical revision/digest, principal/device/installation/namespace/targets/effects/build policy/budgets/expiry/revocation. Routine authorized repeat проходит без нового вопроса. Source/AI text не создаёт grant. Scope diff при новой destination/root/effect идёт в конкретное изменение настройки. Проверять до enqueue и непосредственно перед эффектом; revocation after completed effect не переписывает историю.

Independent STOP — локальный control path вне рабочего model/ASR/job slot. Priority channel и durable cancellation epoch/fence в существующем Core; краткий control transaction не ждёт worker-held long DB transaction. Никаких долгих транзакций при внешнем IO. STOP blocks new lease/dispatch; pending -> CANCELLED_BEFORE_DISPATCH, running -> cancellation_requested с observed COMPLETED/CANCELLED/UNKNOWN. Revoked worker не может publish fresh result. Hard terminate лишь managed child при доказанном ownership и timeout; unknown remote effect не становится cancelled. Reconciliation/readback допустим как read-only recovery, новый write/remote effect ждёт explicit resume + current checks. Если Core завис/не отвечает, local UI сообщает STOP_PENDING/UNCONFIRMED; не утверждать немедленно stopped. Замерять request->durable fence и request->last new dispatch отдельно.

7. ОДИН INTEGRATION PR И МИГРАЦИЯ
Внутренние commits: audit/DTO -> packet+gateway -> data lifecycle -> temporal retrieval -> desktop -> capabilities+STOP -> integration+Windows receipts. Пять workstreams имеют исходный DAG; WS-017 ждёт WS-016, desktop ждёт packet и backup interfaces. Все definitions идут одному owner; сначала add/read-compatible поля, затем backfill на копии, затем switch writers. Точные DDL и files не генерировать до audit текущей schema. Unknown future fields исходного импортного документа сохраняются raw, но execution DTO strict reject unsupported.

Старые browser read-only flows и ручная task передача проходят regression. Profile import/upgrade replay не создаёт duplicate sources. Ошибка staged export/restore оставляет прежний active descriptor. При irreversible migration binary downgrade запрещён; restore проверенный pre-migration snapshot с visible loss boundary. Scope/credential/build evidence после restore требуют новой проверки, historical receipt остаётся historical.
