# ROADMAP-PR-012+013 — единый большой PR

**Название:** Полный жизненный цикл источников: repo snapshots и delta вместе с документами, медиа, web/RSS и GitHub history. Целевой репозиторий: `BobIvans/scaling-chrome-extensions`. Это *описание реализации*, не код, открытый GitHub PR или свидетельство merge.

## Как использовать

1. Передать coding-чату оба исходных ZIP и этот пакет; начать с `EXECUTE_THIS_PR_RU.txt`.
2. Сверить `AGENTS.md`, актуальный `main` SHA, существующие owners и открытые PR. Старый snapshot из исходного пакета — историческое свидетельство, не current-state proof.
3. Реализовать внутренние этапы WS-002, WS-003, WS-006, WS-009, WS-010, WS-011 в **одной целевой ветке и одном итоговом code PR**, если фактический код и CI позволяют; при необходимости делать промежуточные commits, не закрывая общий scope.
4. Сопоставить каждый пункт `CRITERION_COVERAGE.json` с реальным тестом или device receipt. План и проверка самого ZIP не означают выполнения критериев.

**Предпосылки:** PR-001, 002, 003, 004, 010, 011. Их GitHub merge, API совместимость и runtime качество требуют проверки. №012 и №013 были параллельной волной в исходном roadmap; объединение не изменяет номера других пакетов. №014 и №015+ теперь потребляют одно объединённое основание. №016 расширяет базовый importer contract, определённый здесь.

**Граница:** read-only GitHub history; запись PR/merge — позднее №018. Media — сохранённые объекты, не live microphone. Future arbitrary protocols, внешние credential grants и полное V5 closure не входят. Не вводить второй SQLite authority, scheduler или Git inventory implementation.

**Важная коллизия исходника:** PR-013 ссылается на «importer protocol №16», а DAG ставит 016 после 013. Здесь вводится минимальный `ImporterV1` как локальная основа; расширения №016 должны быть совместимыми и не являются prerequisite для сборки этого PR. Исходная граница WS-006 говорит «CAS — №15», хотя само название №012 включает CAS; здесь зафиксирован ограниченный CAS reuse immutable bytes, общий storage/GC/backup остаётся за canonical owner и дальнейшей работой №015/014.
