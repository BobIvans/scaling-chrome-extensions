BACKUP, RESTORE И SYNC — proposed service algorithm

Backup lifecycle: REQUESTED -> PINNING -> COPYING -> VERIFYING -> COMPLETE; ошибки FAILED, cancel CANCELLED с очищаемым staging. COMPLETE только после DB integrity + hash каждого reachable blob + manifest references. Partial artifact не активируется и не именуется complete.

1. Existing owner принимает destination reference, namespace, backup policy и operation_id. Validate destination ownership/access/free space, запрет backup внутрь собственного corpus recursion, resource budget. Create backup run record через current coordinator.
2. Зафиксировать publication boundary с writer coordinator. Выбрать generation G и event watermark E; запрет GC reachable objects, создать pin lease. Согласованный DB snapshot получить через поддерживаемый текущим owner API. При необходимости удержать краткий publication barrier, пока DB backup и enumeration referenced objects получают одну generation. Если нельзя доказать совместимость snapshot и enumeration, artifact INCONSISTENT, повтор с новым operation attempt.
3. Enumerate reachable objects из самого frozen DB snapshot, не из нового live head. Pin references сохранять до публикации/отмены. CAS blobs immutable: hash verify streamed copy, generation не меняется от capture новых sources. Если object отсутствует => MISSING_OBJECT с точным ref; завершение запрещено. При expiry backup pin GC не удаляет staging-owned referenced objects до reconciliation coordinator.
4. Event tail за E не включать как будто уже applied в snapshot. Если events archive сохраняется целиком, указать applied watermark и tail unapplied. Job events и state query compare на G; active external effect описывается как historical state needing reconciliation.
5. Manifest: backup_id, namespace, generation, schema, build compatibility, DB SHA, object refs/SHA/bytes, event watermark, source heads, overlay/relations digest, tombstone epoch, derivation rebuild policy, encryption status, key refs. Temp file flush/verify -> manifest complete marker -> atomic artifact rename. Garbage cleanup только owned staging, receipt сохраняется.

Конкретная схема DB принадлежит actual migration owner. SQLite online backup решает DB copy; координация CAS/events/pins здесь — proposed application design, не обещание API SQLite. Если текущая архитектура позволяет brief quiescence snapshot, это допустимый baseline; latency pause измеряется и видна. Backup во время permitted import/job writes проверяется fault corpus. Не копировать живые DB/WAL/blobs папкой без generation contract.

Restore lifecycle: STAGED -> VERIFIED -> MIGRATION_REHEARSED -> ACTIVATION_READY -> ACTIVATED. Повреждённый artifact -> REJECTED. Restore никогда не заменяет current до полного report. На clean isolated path проверить ZIP traversal, symlinks/absolute paths, integrity, object hashes, references, heads/overlays/labels/relations, FTS rebuild queries. Staging path не является production profile. Unknown newer schema -> UNSUPPORTED_SCHEMA + сохранить artifact.

Tombstone rule: если restore должен стать текущим namespace, объединить trusted current deletion ledger с restored ledger, применить max epoch/source-specific tombstone refs; current removed version не возвращать автоматически. Нет trusted deletion ledger при полном disk loss => recovery namespace и явная дата среза/выбор; не заявлять отсутствие resurrect. Delete alias отличается от source revision и общего CAS blob. Shared blob удаляется только после проверки allowed reachable refs, legal retain refs, active pins и выбранной retention policy. Old snapshots могут содержать bytes: UI перечисляет их и cleanup status. External copy не заявляется удалённой.

Migration rehearsal: copy of restored data -> preflight schema/free space -> step journal -> compare counts/relation sets/hashes/exact queries -> supported application open -> interruption/restart test -> rollback compatibility. Не переносить DB file hash как oracle после migration: физическая layout меняется; logical invariant сравнивается отдельно. User corrections и aliases не теряются. Schema downgrade только compatible explicit matrix; иначе use verified pre-migration snapshot, показывая последующие записи и recovery choice.

Activation: остановить новые jobs, дождаться/reconcile текущих owner leases, fence old generation, close writers/connections. Persist activation journal old/new path and schemas. Atomically replace active descriptor; reopen single owner; readers get new generation; run health exact query. Crash до/после descriptor swap определяется journal, не попыткой «найти newest DB». Старый worker не пишет в restored corpus. Task history/UNKNOWN сохраняется; dispatch_allowed=false until new grant/build/adapter checks. Credential refs могут отсутствовать; secret material и grants автоматически не активировать. Installation runtime version не восстанавливать из чужого archive.

Retention classes: raw original, imported attachment, transcript, derived text/index, packet/projection, log, temporary audio, backup. Default originals preserve until explicit policy; cache TTL proposed configurable, без искусственного cap sources. Impact preview содержит affected relations/packets/backups и shared refs. Delete mark first -> hide current -> invalidate derived -> cleanup reachable analysis -> audit minimum reference. После lease completion recheck tombstone epoch до publication, не resurrect deleted derived. Recovery raw и privacy-redacted audit имеют разные permissions.

Optional portable sync: экспорт immutable selected objects + event envelope origin_device_id/event_id/parent_revision/namespace. Import staging verifies all hashes and scope; replay same event ID/same payload no-op; same ID/different payload conflict. Concurrent note revisions retain both and create conflict; не last-write-wins clock. Foreign namespace needs configured mapping, local execution grants не синхронизируются. Rebuild indexes locally. Никакого shared writable SQLite и второго runtime. Network server/encryption/key recovery — separate profile qualification; локальная offline import/export работает без cloud account.

Encryption decision: optional encrypted profile остаётся OPEN до выбора поддерживаемого crypto provider и key recovery rehearsal. Не делать самодельный шифр и не создавать «encrypted=true» fixture как evidence. Plain local backup имеет explicit access policy; Windows ACL/OS credential provider должны быть проверены separately. Secret canary во всех архивах, logs и screenshots проверяется в device runbook.
