РЕШЕНИЯ И УТОЧНЕНИЯ, КОТОРЫЕ НЕЛЬЗЯ ПОТЕРЯТЬ

D1. Desktop имеет приоритет над обязательной Chrome extension.
    Источник: M002; Chrome/browser остаётся возможным источником и адаптером.
D2. Ближайшая цель — полный контекст и перенос в AI; запуск бота — будущая цель.
    Источник: M002 «now just agregate context and data to resend to AI».
D3. Все доступные исходные слова сохраняются; summaries не заменяют их.
    Источник: M005. Недоступные сообщения отмечаются, а не реконструируются как цитаты.
D4. Ограничения количества документов не должны приводить к потере хвоста.
    Источник: M002. Pagination/part size/ресурсные бюджеты — механизмы обработки,
    а не основание считать часть библиотеки несуществующей.
D5. Параллельность нужна и для записи наблюдений.
    Источник: VOICE-USER-EXCERPT-01 (сохранённый фрагмент). Уточняет старое
    «параллельно только чтение» в legacy docs. Несколько независимых append-only
    producers и isolated code worktrees допустимы; совместный mutable resource
    координируется отдельно. Старые тексты не переписаны задним числом.
D6. Термин «один writer» уточнять объектом: файл, ветка, UI focus, операция.
    Это архитектурная интерпретация ассистента D5, не новая дословная цитата.
D7. «Любая команда» — направление расширяемости, не готовая универсальная capability.
    Источники: M003, OCC-USER-01. Неизвестное действие порождает конкретный R&D шаг.
D8. Собственные предложения ассистента разрешено добавлять, но авторство различать.
    Источник: M005. AI-RND-01…12 не приняты пользователем как окончательный дизайн.
D9. Исторические qualified/green выводы проверять против нужных revisions и inputs.
    Это рекомендованный evidence contract из прежних пакетов, не запуск проверок.
D10. Существующие owners, task IDs и code evidence сохраняются.
     Восстановленное архитектурное решение из связанных пакетов. Сверить с актуальным
     repo перед правкой; не создавать второй независимый scheduler/store по summary.

ОТКРЫТЫЕ ВОПРОСЫ ДЛЯ БУДУЩЕЙ РЕАЛИЗАЦИИ
• Какой текущий bot checkout/ZIP и branch является выбранным источником?
• Где живут canonical store/action queue существующего SCE в актуальном коде?
• CPU/RAM/GPU, аудиоустройства и ограничения конкретного Dell Windows 11?
• Какие экспорты истории и private sources доступны для импорта?
• Какой точный Laya model/backend/version испытывается по сохранённым ссылкам?
• Какой первый qualification entrypoint уже существует и чем проверяется?
• Какие реальные ежедневные команды станут baseline набора измерений?

Эти вопросы не блокируют сохранение архива. Ответы понадобятся для конкретных
следующих изменений. Недостающие факты не заполнять догадками нового чата.
