ЛОКАЛЬНЫЙ СКАНЕР КАНДИДАТОВ НА CODE SMELLS — версия 1.0.0

Что работает
============
repo_smells.py рекурсивно читает все обнаруженные .py в локальной папке.
Он ничего не импортирует из проекта, не запускает код, не устанавливает
зависимости, не обращается к RPC, API или кошелькам. Нужен Python 3.11+.
Это отдельный инструмент R&D, а не завершённая интеграция Laya.

Windows PowerShell:
  py -3 .\repo_smells.py "C:\code\my-bot" --output "C:\reports\bot-smells.json"

Если Python-пакеты лежат в src:
  py -3 .\repo_smells.py "C:\code\my-bot" --output "C:\reports\bot-smells.json" --import-root src --long-function-lines 100

Параметр --import-root можно повторять. По умолчанию корень импортов — сама
папка репозитория. Порог размера функций по умолчанию 80 физических строк;
это настраиваемый критерий находки, а не ограничение объёма анализа.

JSON-отчёт требуется записывать СНАРУЖИ сканируемого репозитория: инструмент
не добавляет и не перезаписывает его файлы. Запись отчёта атомарная через
временный файл. При остановке до замены новый итоговый отчёт не готов;
старый файл с тем же именем может остаться — проверяйте generated_at и хеш.
Код выхода 0 означает, что отчёт создан; это не отсутствие проблем.
Код выхода 2 означает ошибку аргументов, корневой папки, памяти или записи.
Принудительная остановка процессом может дать другой ненулевой код выхода.

Новые функции
=============
SMELL-01 Полный рекурсивный реестр .py: относительный путь от корня, абсолютный
         путь, SHA-256 исходных байтов, размер, mtime, статус чтения и разбора.
SMELL-02 Маркеры eval/exec, буквального shell=True, bare except и except/pass.
SMELL-03 Длинные функции с именем, строками и настраиваемым порогом.
SMELL-04 Дубли тел функций по нормализованному AST без координат и ведущих
         docstring; одинаковые basename разных папок сохраняются отдельно.
SMELL-05 Граф разрешимых локальных импортов с настраиваемыми import roots.
SMELL-06 Циклические компоненты графа с исходными строками и рёбрами; алгоритм
         не зависит от лимита рекурсии Python для количества модулей.
SMELL-07 Отдельный список внешних/неразрешённых, wildcard и динамических
         импортов. Он явно показывает неполноту графа зависимостей.
SMELL-08 Отдельные статусы binary, syntax/decode/read/stat/list errors,
         пропущенных symlink/reparse point и изменений во время чтения.
SMELL-09 Детерминированный хеш наблюдавшегося реестра для привязки результатов
         к версии байтов; каждой находке присвоен стабильный ID.
SMELL-10 Отчёт STATIC_CANDIDATE для дальнейшего тегирования/проверки агентом.

Как трактовать результат
========================
Каждая находка — STATIC_CANDIDATE и requires_review=true. Это гипотеза,
которую можно связать с данным в библиотеке по path + source_sha256 +
start_line/end_line, а затем проверить тестом или обзором человека/LLM.
Колонки AST start_column/end_column — байтовые смещения UTF-8, не номер
видимого символа. Номера строк начинаются с 1. Конец диапазона колонок
исключающий, как в Python AST.

Пример меток для элемента библиотеки:
  data_kind=code_evidence
  project=my-bot
  evidence_status=STATIC_CANDIDATE
  claim_type=possible_maintainability_issue
  source_sha256=<из отчёта>
  source_path=<полный относительный путь>
  finding_id=<из отчёта>
  rule=BARE_EXCEPT
  next_action=review_exception_handling

Перепроверка меняет оценку утверждения, но не должна затирать исходную
находку. Добавляйте отдельную проверку с evidence_status=CONFIRMED,
REFUTED или UNKNOWN, причиной, версией исходника и ссылкой на тест.

security_audit_pass, runtime_tests и live_bot_readiness всегда NOT_RUN.
COMPLETE_FOR_DISCOVERED_PYTHON означает только завершённый разбор найденных
.py. COMPLETE_WITH_GAPS означает, что есть пропуски/ошибки. Ноль находок не
доказывает безопасность, прибыльность, отсутствие запахов или готовность
бота к live. Скрипт не делает таких выводов.

Ограничения и точность
=====================
Нет произвольного ограничения на 20 документов, 300 файлов или общий размер
репозитория. Однако файл целиком, AST и итоговый JSON находятся в RAM.
Физическая память, диск и ограничения парсера существуют. Этот инструмент
не обещает обработку любого объёма без ошибок; не заменяет архиватор данных.
Языки, отличные от Python, файлы .pyi и содержимое архивов не анализируются.

Оригиналы сохраняются неизменными: читаются только исходные байты. Поля
хеша не являются Git commit SHA. Для воспроизводимости используйте
неизменяемую копию/checkout. Проверка stat до/после чтения обнаруживает
обычные изменения, но не создаёт атомарный снимок всего репозитория.
Инструмент не защищён от враждебной одновременной подмены каталогов локальным
процессом. Обнаруженные symlink и Windows reparse points пропускаются;
их цели не сканируются. Это явно отражается в статусе, а не скрывается.

Разрешение импортов консервативное: sys.path, installed packages, __all__,
атрибуты модулей, плагины и runtime import hooks не исполняются. При
совпадении нескольких локальных модулей имя помечается как неоднозначное.
Карта строится по успешно разобранным файлам; файл с syntax error не может
стать доказанным узлом. Неизвестный модуль не объявляется «отсутствующим»:
он может быть установленной зависимостью или требовать других import roots.

Условные импорты и импорты внутри функций входят в статический граф. Цикл
в нём не доказывает цикл выполнения или падение программы. Динамические
вызовы __import__, importlib.import_module и распознаваемые aliases идут
в отдельный список, включая вызовы с буквальным именем. Другие косвенные
способы импорта могут быть пропущены.

Имена eval/exec и importlib могут быть переопределены. shell=True может
принадлежать пользовательской функции. Поиск дубликатов не переименовывает
переменные и не сравнивает внешнее окружение/аргументы; sync/async функции
с одинаковым телом тоже могут иметь разную семантику. Это кандидаты для
обзора, не автоматическое разрешение удалить или переписать код.

Проверка
========
  py -3 -m unittest discover -s . -p "test_repo_smells.py" -v

Тесты проверяют реальные исходники во временных папках: отсутствие их
исполнения/изменения, hashes/spans, дубли basename, invalid/binary source,
ошибку чтения, пропуск ссылок, локальные/relative/src импорты, циклы,
динамические импорты, >300 файлов, 2500 узлов графа и реальный CLI.
Windows запуск и Windows junction отдельно требуют проверки на Dell.
