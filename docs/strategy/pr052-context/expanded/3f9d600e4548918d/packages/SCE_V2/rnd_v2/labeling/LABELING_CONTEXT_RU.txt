МЕТКИ ДЛЯ КАЖДОЙ ЧАСТИ КОНТЕКСТА — ИСПОЛНЯЕМЫЙ ОФЛАЙН-ПРОТОТИП

Назначение
label_context.py читает пакет формата sce.desktop.export.v1, созданный Context Store,
и создаёт отдельный производный индекс. Исходные files.jsonl, оригиналы и TXT не
изменяются. Никаких сетевых запросов, запуска чужого кода или обращения к Laya нет.
Это добавление к изолированному desktop-прототипу, а не новая production-база SCE.
В production все адаптеры должны пользоваться одной канонической библиотекой SCE.

Запуск из корня нового ZIP, Windows 11 / Python 3.11+

py -3 rnd_v2\labeling\label_context.py build C:\Context\repo-export C:\Context\repo-labels --namespace flashloan-main --project flashloan --tag research
py -3 rnd_v2\labeling\label_context.py goal C:\Context\repo-labels C:\Context\goal-tests --goal "flashloan tests qualification"
py -3 rnd_v2\labeling\label_context.py goal C:\Context\repo-labels C:\Context\all-context --goal "Полная проверка репозитория" --include-all
py -3 rnd_v2\labeling\label_context.py diff C:\Context\repo-labels C:\Context\repo-labels-next C:\Context\revision-diff.json

Все выходные имена должны быть новыми. Для нового snapshot используйте следующий
каталог. Не переиспользуйте каталог существующего результата.
Если модуль находится рядом с этим документом, замените rnd_v2\labeling\label_context.py на
реальное расположение label_context.py.

API для интерфейса
build_labels(pack, destination, namespace=None, project=None, tags=(), span_chars=4096,
             progress=lambda message: None, cancel=lambda: False)
assemble_goal(labels_dir, goal, destination, include_all=False,
              progress=lambda message: None, cancel=lambda: False)
compare_revisions(old_labels, new_labels, destination)
build_labels и assemble_goal возвращают словарь отчёта; cancel=True вызывает
Cancelled и удаляет временный результат при обычном завершении Python. Жёсткое
завершение процесса/отключение питания может оставить .labels-* или .goal-*;
это незавершённые временные каталоги. Не считайте их готовым результатом.

Что реально создаётся
1. labels.jsonl — одна запись на источник, каждый текстовый span и каждое сообщение
   conversations.json, если Context Store уже создал messages.jsonl.
2. graph.json — связи derived_from и reply_to. Последние используют объявленный
   parent; это не восстановление всех невидимых ветвей истории.
3. manifest.json — хеши входов/результатов, счётчики, параметры и известные пробелы.
4. goal/context.jsonl + context.txt — выбранные кандидаты с полными локаторами.
5. goal/coverage.jsonl — решение для КАЖДОЙ записи: INCLUDED, EXCLUDED, UNKNOWN
   или METADATA_ONLY; ни одна запись не исчезает из отчёта.
6. goal/report.json — цель, запрос, хеши, счётчики и НЕПРОВЕРЕННЫЙ смысл результата.
7. revision-diff.json — изменённые/добавленные/удалённые источники и необходимость
   пересобрать зависимые документы контекста.

Метки: 14 поддерживаемых измерений
source, authorship, semantic_type, project, goal, time, status, evidence,
confidence, sensitivity, machine_parse, language, execution, custom.
Не каждое измерение заполняется автоматически: неизвестное не подменяется догадкой.
Общее расширенное предложение содержится в universal-label-facets.SPEC.json.

У каждой метки есть value — исходное значение; tag — нормализованный ключ;
status — ASSERTED / SUGGESTED / UNKNOWN; basis — происхождение; confidence.
confidence=null у простых правил: число вероятности не выдумывается.
ASSERTED означает «явно пришло из этого источника/параметра», а не «объективно доказано».
Роль user/assistant у сообщения не удостоверяет личность или правильность сказанного.
Нельзя считать текст ассистента заявленной целью пользователя без отдельного решения.
Исходные annotations сохраняются полностью, даже если из строки выделены метки.
Теги проходят Unicode NFKC, casefold, очистку управляющих знаков и пунктуации.
Оригинальное значение сохраняется для аудита; теги никогда не исполняются.

Что предлагает текущая эвристика
Вопрос, возможная цель, возможная задача, упоминание тестов, web3, возможное решение,
кандидат «код» по расширению, наличие русских/латинских букв и упоминание секретов.
Каждая смысловая метка SUGGESTED. Фраза «API key» не доказывает наличие ключа.
Отсутствие этой фразы не доказывает отсутствие секретов: sensitivity=unclassified
остаётся UNKNOWN. Метка unverified_content не превращается в VERIFIED от совпадения
ключевых слов. Никаких TRUE-решений о готовности бота этот модуль не принимает.

Точность, пути, версии
source_id = namespace + точный полный путь внутри snapshot + номер повторения
того же пути. Повторяющиеся пути ZIP сохраняются отдельно. namespace желательно
задавать явно и одинаково между импортами: например flashloan-main.
revision_id/content_revision_id зависят от SHA-256 оригинала и типа записи.
span_id дополнительно зависит от диапазона и SHA-256 текста. Изменение оригинала
инвалидирует все зависимые spans, даже если часть текста не изменилась.
annotation_revision_id отдельно учитывает пользовательские метки/проект/annotations.
diff требует пересборку контекста при любом изменении labels.jsonl, в том числе
новом разбиении, metadata или messages.jsonl. Это консервативное правило: иногда
оно попросит пересборку при техническом изменении snapshot без изменения смысла.
Перестановка одинаковых путей в ZIP меняет идентичность duplicate_occurrence.

Локаторы spans — [start,end) в декодированных Unicode code points. Это не байты
и не токены модели. encoding записан явно; CRLF не нормализуются. UTF-8 BOM
сохраняется в тексте; BOM UTF-16/32 обрабатывается декодером, остаётся в оригинале.
В JSONL присутствуют SHA-256 оригинала, относительный путь объекта, полный путь,
snapshot, entry и ordinal. Декодируем только TEXT_COMPLETE; PDF/Office/медиа,
неподдерживаемые кодировки и прочие RAW_ONLY остаются оригиналами + UNKNOWN.
TEXT_COMPLETE без оригинала — ошибка входного пакета, а не успешная пустая запись.

Границы доказательности
Хеши проверяют целостность относительно данного пакета, а не личность автора.
Количество строк files.jsonl сверяется с index.json. Полнота исходного репозитория
пока REPORTED_BY_EXPORT_MANIFEST_NOT_INDEPENDENT_SOURCE_INVENTORY. Для независимой
сверки ZIP используйте verify_pack.py; реальный Git inventory требует отдельного
адаптера, привязанного к commit SHA. Непредоставленные чаты не восстанавливаются.
messages.jsonl сохраняется по всем представленным ролям/ветвям, без фильтра user-only.
Его связь с исходным conversations.json здесь повторно не разбирается: поле
ORIGINAL_HASH_VERIFIED_MAPPING_NOT_REVALIDATED честно указывает этот пробел.
reply_to может указывать на отсутствующую запись (parent может быть ID узла, а не
ID сообщения). При повторяющихся message IDs ссылка выбирает первое повторение;
сама каждая запись сохраняется отдельно. Для точного дерева нужен новый адаптер
ChatGPT, экспортирующий mapping node IDs и сверяющий их с оригинальным JSON.

Поиск цели и полное покрытие
goal — лексический поиск кандидатов по тексту, путям и меткам. Не семантический RAG.
Нет top-20/top-k. Все совпадения включаются; все несовпадения учитываются отдельно.
EXCLUDED означает «не совпало с текущим лексическим запросом», а не «не относится к цели».
Результат может пропускать синонимы, склонения, фразы на границе spans и зависимости
между файлами. Для полного прохода используйте --include-all. Все доступные spans
и сообщения попадут в контекст; RAW_ONLY всё равно останутся UNKNOWN.
Если нет значимых поисковых слов, текст помечается UNKNOWN; используйте --include-all.
Сообщения представлены и внутри исходного JSON, и как удобная производная: для
контроля полноты такое дублирование допустимо, но downstream AI должен его учитывать.
Сборка контекста не означает чтение его AI, прохождение тестов или выполнение цели.
goal_achieved=NOT_RUN, laya_inference=NOT_RUN, semantic_relevance=NOT_VERIFIED.

Ресурсы и сохранность
Нет произвольного общего лимита документов, файлов, ZIP или текста. span_chars —
размер сегмента, не предел обработки. Диск/память/контекст провайдера конечны.
Оригиналы не копируются второй раз: держите исходный pack рядом с индексом и
резервируйте оба каталога. Только индекс не заменяет архив оригиналов.
Большинство чтений/записей потоковые. Таблица source_by_entry, словарь дублей,
одна JSONL-строка сообщения и diff вмещаются в RAM: сверхбольшие экспорты требуют
SQLite join/потокового JSON адаптера в следующем этапе. Не утверждаем unlimited RAM.

R&D следующие шаги
— Экстракторы PDF/Office/OCR/ASR со страницами, координатами, таймкодами и отчётом
  остатка RAW_ONLY; исходник всегда отдельный неизменяемый объект.
— Метки источника/роли/цели/решения/гипотезы/возражения/отменённой цели/цитаты.
— Связи supersedes, contradicts, supports, requires, blocks, owned_by, derived_from.
— Иерархия целей + сроки + происхождение решения, а не только плоский набор тегов.
— Laya предлагает choice/score, умеет воздержаться; принятые метки имеют автора,
  версию модели, калибровку на RU/EN и ссылку на доказательство. Это пока спецификация.
— Идемпотентная маркировка новых/изменившихся spans, оценка precision/recall по
  пользовательской разметке, выборка спорных тегов для уточнения и обратимые исправления.
— Semantics/dependency retrieval объединяется с exhaustive ledger: найденное,
  исключённое и неизвестное сохраняются раздельно, без ложного «прочитано всё».

Проверка
python -m unittest discover -s app -p "test_label_context.py" -v
На этапе разработки выполнены 16 тестов: >20 источников, 101 совпадение без top-k,
полные пути, Unicode/CRLF/UTF16, дубли, роли/ветви, изменение контента/annotations,
RAW_ONLY, повреждённые хеши, escape-пути, пустой запрос и отмена с очисткой.
Windows GUI и реальное Laya inference не выполнялись в этой Linux-среде.
