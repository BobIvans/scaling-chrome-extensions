1. Building Blocks & Models for a Perplexity-Class System (Web3-Optimized)
 
Core stack to focus on:
 
 
Search + Crawl layer: Firecrawl (self-hostable, structured Markdown/JSON output), Morphic or Farfalle (open Perplexity clones), SearXNG + Tavily/Exa as fallbacks, searchts for keyless multi-provider fusion.
 
Retrieval: Hybrid dense + BM25 + graph expansion. Use Qwen3-Embedding (0.6B–8B, top MTEB) or EmbeddingGemma-300m for local; BGE-M3 for multilingual. Always add a reranker (Qwen3-Reranker-4B or Ettin family / bge-reranker-v2-m3).
 
Knowledge & Memory: GraphRAG-style (Neo4j or Kuzu) + Mem0 / Letta / Zep for long-term agent memory with reconsolidation.
 
Orchestration: LangGraph or CrewAI for multi-agent research (scout → synthesizer → critic). MCP as the universal tool interface.
 
Long-context reasoning models: Qwen3 series (strong open weights), local code models (IQuest-Coder variants), or cloud long-context models for synthesis.
 
UI surface: BlockNote or AFFiNE-style block editor + shadcn/ui + Tailwind for the adaptive front-end.
 
 
This combination beats basic Perplexity by adding authenticated sources, graph reasoning, temporal state, and direct MCP exposure to agents.

4. Exact Schema for the Knowledge Library (Core)
 
Use a hybrid document + graph store. Recommended core types (JSON / TypeScript style):
 
TypeScript


interface KnowledgeItem {
  id: string;
  type: "repo_chunk" | "web3_pair" | "strategy" | "goal" | "session" | "research_note";
  title: string;
  content: string;               // Markdown or structured text
  summary: string;               // Dense LLM-generated summary
  categories: string[];          // e.g. ["arbitrage", "solana", "progress"]
  entities: { id: string; label: string; type: string }[];
  relations: { from: string; to: string; type: string; weight?: number }[];
  embeddings?: number[];         // or reference to vector store
  temporal: {
    created: string;
    updated: string;
    valid_from?: string;
    valid_to?: string;           // for supersession
  };
  provenance: {
    source: string;              // repo path, URL, API endpoint
    confidence: number;          // 0-1
    citations: string[];
  };
  metadata: Record<string, any>; // chain, pair, progress_score, etc.
  goals?: string[];              // linked executable goals
}




 
Graph layer adds typed nodes (RepoFile, Function, Pair, Strategy, Goal) and edges (CALLS, DEPENDS_ON, ARBITRAGES, SUPERSEDES, PROGRESSES_TO).

6. Evaluation Metrics for “Golden Intelligence” Quality
 
Track these on every export / session:
 
 
Density: tokens of useful signal / total tokens (target > 0.7).
 
Coverage: % of relevant entities/relations included vs ground-truth sample.
 
Freshness: average age of included facts + % superseded facts correctly marked.
 
Actionability: number of concrete next steps or executable goals generated.
 
Citation faithfulness: % of claims with verifiable provenance.
 
Downstream utility: measured by how much my subsequent reasoning accuracy or speed improves (human or automated judge).
 
Reconsolidation gain: improvement in answer quality after memory update loops.
 
 
Run automated evals on a fixed set of repo + web3 queries after every major change.
