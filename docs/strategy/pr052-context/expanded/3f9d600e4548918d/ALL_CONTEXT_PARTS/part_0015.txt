ЛОКАЛЬНАЯ БИБЛИОТЕКА → ЦЕЛЬ → ПРОВЕРЯЕМОЕ ДЕЙСТВИЕ
Версия R&D V2, 3 октября 2026. Это развитие предыдущего desktop ZIP.

Предлагаемый продукт: локальный рабочий стол для собственных данных, целей и проверяемых действий.
Первый законченный сценарий: импорт repo/чатов → полный архив → разметка → цель → пакет контекста → анализ → проверяемый следующий шаг.
Голос — ещё один способ задать ту же задачу; он не создаёт отдельную систему полномочий.
Кнопки: «Говорить», «Собрать контекст», «Показать источники», «Проверить проект», «Подготовить изменение», «Продолжить», «Стоп».

РОЛИ СЛОЁВ
1. Capture: сохраняет неизменённый оригинал, его hash, источник, полный путь/ID и время получения.
2. Parse: создаёт текст/транскрипт/AST как отдельную производную версию. Нераспознанное хранится RAW_ONLY.
3. Label: метаданные, предложенные semantic tags и исправления пользователя. Тег не является фактом о мире.
4. Retrieval: находит цель, актуальные решения, исходники, зависимости, прежние ошибки, counterevidence.
5. Laya: локальный выбор зарегистрированной операции, relevance/intent/priority, маршрутизация и отказ при неоднозначности.
6. Planner/coder: локальная LLM либо выбранный API строит план/patch. Laya сама по себе не является генератором произвольного кода.
7. Executor: существующий automation_core/queue вызывает конкретный зарегистрированный handler с валидированными аргументами.
8. Verifier: проверяет наблюдаемый результат, возвращает TRUE/FALSE/UNKNOWN/NOT_RUN и привязки к версии.
9. Memory: сохраняет результат, failed attempts и связи с исходной целью. После изменения исходников старое evidence становится stale.

ДВА ВИДА ПОЛНОТЫ
Полный архив означает: каждый входной объект учтён, оригинальные байты сохранены, ошибка не скрыта.
Полное понимание означает: нужные объекты распознаны и действительно просмотрены. Это отдельная метрика.
Архив может содержать миллионы записей; один вызов модели всё равно имеет конечное окно. Решение — полный inventory, потоковые chunks, coverage ledger, несколько проходов и cross-file review.
Отсутствие top-20 в библиотеке не требует слать всю личную жизнь одному API. Пакет для цели должен показывать включённые, невключённые, неподдерживаемые и устаревшие источники.

КАК ЭТО ВЫГЛЯДИТ ДЛЯ WEB3
Команда: «Продолжи квалификацию бота, выясни, что мешает paper-наблюдению».
Система сохраняет транскрипт → разрешает цель/проект → сверяет HEAD → собирает код, config, tests и прошлые blockers → строит mission → запускает известные проверки → сравнивает наблюдения с критериями → сохраняет receipt и следующий blocker.
Оффлайн replay, live data observation, paper simulation и отправка транзакции — разные режимы с отдельными доказательствами. Отсутствие ошибок в unit tests не означает пригодность стратегии или прибыльность.

УНИВЕРСАЛЬНАЯ РАЗМЕТКА ДАННЫХ

Не существует одного идеального semantic тега. Разделяем независимые фасеты и храним основание каждого значения.

Обязательная оболочка любого объекта:
identity: source_id, logical_item_id, revision_id, content_hash, original_locator;
capture: captured_at, connector/version, scope, complete/partial/error, raw_blob_ref;
authorship: автор, role(user/assistant/system/tool/unknown), conversation/message/branch/reply IDs;
time: published_at, edited_at, observed_at, valid_from/to (не подставлять capture-time как publication-time);
representation: mime, language, modality, parser/version, text_state, spans (bytes/lines/page/time interval);
provenance: derived_from, referenced_by, exact repo SHA, file hash, workflow run;
knowledge: quote/assertion/hypothesis/decision/goal/task/constraint/evidence/counterevidence;
epistemic: OBSERVED/INFERRED/LATENT/UNKNOWN; отдельная truth TRUE/FALSE/UNKNOWN/NOT_RUN;
project: repo/domain/owner/symbol/dependency/goal_id (несколько значений допустимы);
lifecycle: proposed/accepted/active/blocked/done/superseded/rejected/archived;
sensitivity: personal/confidential/secret/unknown, allowed egress, access scope;
label provenance: asserted_by, suggested_by, method/version, confidence/calibration, supporting_span, corrected_at.

Точность полей разная. Hash/path/messageID можно вычислить; intent и semantic relevance — предположения.
Unknown не заменяется пустым ложным фактом. Model confidence не является доказательством истины или разрешением выполнить действие.
Авторство и provenance относятся к каждому фрагменту. Две копии одного текста могут иметь одинаковые bytes и разные источники.

Примеры:
• «Хочу локальную библиотеку» в user message → goal candidate, author=user, source span; после явного принятия goal=ACTIVE.
• «Все тесты прошли» в assistant message → CLAIM, truth=UNKNOWN до test artifact с точным SHA.
• result.xml из запущенного теста → EVIDENCE, конкретные test cases/skip/fail; validity только для его SHA/config.
• TODO или shell=True в исходнике → STATIC_CANDIDATE, не автоматически bug/exploit.
• фотография/аудио без parser → raw сохранён, interpretation=NOT_RUN; OCR/ASR даст отдельную derivative, оригинал остаётся.

Life library:
Личные разговоры, документы и Telegram imports должны иметь собственные scopes. Голосовая цель выбирает область библиотеки; найденная секретная строка не даёт разрешения отправить её внешнему API.
Искать «всё моё» — значит учесть все подключённые/импортированные источники. Приватные каналы без пользовательского export/доступа не видны приложению.
Удаление/редактирование требует tombstone/revision и пересчёта derivative context; старый выбор может сохраняться как исторический snapshot с явной датой.

Как оценить «идеальные теги»:
Создать gold set собственных русских/английских фрагментов; пометить source-span, semantic type, goal links, counterexamples и abstain cases; split по разговорам/времени, а не соседним chunks.
Сравнить heuristic baseline, Laya, local LLM; считать precision/recall по типу, retrieval recall, calibration, correction time и p95 latency.
Порог для выбора следующего действия калибровать отдельно от порога для выдачи поисковых подсказок.

Ttask = Tendpointing + TASR + Tretrieval + Tplanning + Texecution + Tverification.

МЕТКИ ДЛЯ КАЖДОЙ ЧАСТИ КОНТЕКСТА — ИСПОЛНЯЕМЫЙ ОФЛАЙН-ПРОТОТИП

Назначение
label_context.py читает пакет формата sce.desktop.export.v1, созданный Context Store,
и создаёт отдельный производный индекс. Исходные files.jsonl, оригиналы и TXT не
изменяются. Никаких сетевых запросов, запуска чужого кода или обращения к Laya нет.
Это добавление к изолированному desktop-прототипу, а не новая production-база SCE.
В production все адаптеры должны пользоваться одной канонической библиотекой SCE.

Запуск из корня нового ZIP, Windows 11 / Python 3.11+

py -3 rnd_v2\labeling\label_context.py build C:\Context\repo-export C:\Context\repo-labels --namespace flashloan-main --project flashloan --tag research
py -3 rnd_v2\labeling\label_context.py goal C:\Context\repo-labels C:\Context\goal-tests --goal "flashloan tests qualification"
py -3 rnd_v2\labeling\label_context.py goal C:\Context\repo-labels C:\Context\all-context --goal "Полная проверка репозитория" --include-all
py -3 rnd_v2\labeling\label_context.py diff C:\Context\repo-labels C:\Context\repo-labels-next C:\Context\revision-diff.json

Все выходные имена должны быть новыми. Для нового snapshot используйте следующий
каталог. Не переиспользуйте каталог существующего результата.
Если модуль находится рядом с этим документом, замените rnd_v2\labeling\label_context.py на
реальное расположение label_context.py.

API для интерфейса
build_labels(pack, destination, namespace=None, project=None, tags=(), span_chars=4096,
             progress=lambda message: None, cancel=lambda: False)
assemble_goal(labels_dir, goal, destination, include_all=False,
              progress=lambda message: None, cancel=lambda: False)
compare_revisions(old_labels, new_labels, destination)
build_labels и assemble_goal возвращают словарь отчёта; cancel=True вызывает
Cancelled и удаляет временный результат при обычном завершении Python. Жёсткое
завершение процесса/отключение питания может оставить .labels-* или .goal-*;
это незавершённые временные каталоги. Не считайте их готовым результатом.

Что реально создаётся
1. labels.jsonl — одна запись на источник, каждый текстовый span и каждое сообщение
   conversations.json, если Context Store уже создал messages.jsonl.
2. graph.json — связи derived_from и reply_to. Последние используют объявленный
   parent; это не восстановление всех невидимых ветвей истории.
3. manifest.json — хеши входов/результатов, счётчики, параметры и известные пробелы.
4. goal/context.jsonl + context.txt — выбранные кандидаты с полными локаторами.
5. goal/coverage.jsonl — решение для КАЖДОЙ записи: INCLUDED, EXCLUDED, UNKNOWN
   или METADATA_ONLY; ни одна запись не исчезает из отчёта.
6. goal/report.json — цель, запрос, хеши, счётчики и НЕПРОВЕРЕННЫЙ смысл результата.
7. revision-diff.json — изменённые/добавленные/удалённые источники и необходимость
   пересобрать зависимые документы контекста.

Метки: 14 поддерживаемых измерений
source, authorship, semantic_type, project, goal, time, status, evidence,
confidence, sensitivity, machine_parse, language, execution, custom.
Не каждое измерение заполняется автоматически: неизвестное не подменяется догадкой.
Общее расширенное предложение содержится в universal-label-facets.SPEC.json.

У каждой метки есть value — исходное значение; tag — нормализованный ключ;
status — ASSERTED / SUGGESTED / UNKNOWN; basis — происхождение; confidence.
confidence=null у простых правил: число вероятности не выдумывается.
ASSERTED означает «явно пришло из этого источника/параметра», а не «объективно доказано».
Роль user/assistant у сообщения не удостоверяет личность или правильность сказанного.
Нельзя считать текст ассистента заявленной целью пользователя без отдельного решения.
Исходные annotations сохраняются полностью, даже если из строки выделены метки.
Теги проходят Unicode NFKC, casefold, очистку управляющих знаков и пунктуации.
Оригинальное значение сохраняется для аудита; теги никогда не исполняются.

Что предлагает текущая эвристика
Вопрос, возможная цель, возможная задача, упоминание тестов, web3, возможное решение,
кандидат «код» по расширению, наличие русских/латинских букв и упоминание секретов.
Каждая смысловая метка SUGGESTED. Фраза «API key» не доказывает наличие ключа.
Отсутствие этой фразы не доказывает отсутствие секретов: sensitivity=unclassified
остаётся UNKNOWN. Метка unverified_content не превращается в VERIFIED от совпадения
ключевых слов. Никаких TRUE-решений о готовности бота этот модуль не принимает.

Точность, пути, версии
source_id = namespace + точный полный путь внутри snapshot + номер повторения
того же пути. Повторяющиеся пути ZIP сохраняются отдельно. namespace желательно
задавать явно и одинаково между импортами: например flashloan-main.
revision_id/content_revision_id зависят от SHA-256 оригинала и типа записи.
span_id дополнительно зависит от диапазона и SHA-256 текста. Изменение оригинала
инвалидирует все зависимые spans, даже если часть текста не изменилась.
annotation_revision_id отдельно учитывает пользовательские метки/проект/annotations.
diff требует пересборку контекста при любом изменении labels.jsonl, в том числе
новом разбиении, metadata или messages.jsonl. Это консервативное правило: иногда
оно попросит пересборку при техническом изменении snapshot без изменения смысла.
Перестановка одинаковых путей в ZIP меняет идентичность duplicate_occurrence.

Локаторы spans — [start,end) в декодированных Unicode code points. Это не байты
и не токены модели. encoding записан явно; CRLF не нормализуются. UTF-8 BOM
сохраняется в тексте; BOM UTF-16/32 обрабатывается декодером, остаётся в оригинале.
В JSONL присутствуют SHA-256 оригинала, относительный путь объекта, полный путь,
snapshot, entry и ordinal. Декодируем только TEXT_COMPLETE; PDF/Office/медиа,
неподдерживаемые кодировки и прочие RAW_ONLY остаются оригиналами + UNKNOWN.
TEXT_COMPLETE без оригинала — ошибка входного пакета, а не успешная пустая запись.

Границы доказательности
Хеши проверяют целостность относительно данного пакета, а не личность автора.
Количество строк files.jsonl сверяется с index.json. Полнота исходного репозитория
пока REPORTED_BY_EXPORT_MANIFEST_NOT_INDEPENDENT_SOURCE_INVENTORY. Для независимой
сверки ZIP используйте verify_pack.py; реальный Git inventory требует отдельного
адаптера, привязанного к commit SHA. Непредоставленные чаты не восстанавливаются.
messages.jsonl сохраняется по всем представленным ролям/ветвям, без фильтра user-only.
Его связь с исходным conversations.json здесь повторно не разбирается: поле
ORIGINAL_HASH_VERIFIED_MAPPING_NOT_REVALIDATED честно указывает этот пробел.
reply_to может указывать на отсутствующую запись (parent может быть ID узла, а не
ID сообщения). При повторяющихся message IDs ссылка выбирает первое повторение;
сама каждая запись сохраняется отдельно. Для точного дерева нужен новый адаптер
ChatGPT, экспортирующий mapping node IDs и сверяющий их с оригинальным JSON.

Поиск цели и полное покрытие
goal — лексический поиск кандидатов по тексту, путям и меткам. Не семантический RAG.
Нет top-20/top-k. Все совпадения включаются; все несовпадения учитываются отдельно.
EXCLUDED означает «не совпало с текущим лексическим запросом», а не «не относится к цели».
Результат может пропускать синонимы, склонения, фразы на границе spans и зависимости
между файлами. Для полного прохода используйте --include-all. Все доступные spans
и сообщения попадут в контекст; RAW_ONLY всё равно останутся UNKNOWN.
Если нет значимых поисковых слов, текст помечается UNKNOWN; используйте --include-all.
Сообщения представлены и внутри исходного JSON, и как удобная производная: для
контроля полноты такое дублирование допустимо, но downstream AI должен его учитывать.
Сборка контекста не означает чтение его AI, прохождение тестов или выполнение цели.
goal_achieved=NOT_RUN, laya_inference=NOT_RUN, semantic_relevance=NOT_VERIFIED.

Ресурсы и сохранность
Нет произвольного общего лимита документов, файлов, ZIP или текста. span_chars —
размер сегмента, не предел обработки. Диск/память/контекст провайдера конечны.
Оригиналы не копируются второй раз: держите исходный pack рядом с индексом и
резервируйте оба каталога. Только индекс не заменяет архив оригиналов.
Большинство чтений/записей потоковые. Таблица source_by_entry, словарь дублей,
одна JSONL-строка сообщения и diff вмещаются в RAM: сверхбольшие экспорты требуют
SQLite join/потокового JSON адаптера в следующем этапе. Не утверждаем unlimited RAM.

R&D следующие шаги
— Экстракторы PDF/Office/OCR/ASR со страницами, координатами, таймкодами и отчётом
  остатка RAW_ONLY; исходник всегда отдельный неизменяемый объект.
— Метки источника/роли/цели/решения/гипотезы/возражения/отменённой цели/цитаты.
— Связи supersedes, contradicts, supports, requires, blocks, owned_by, derived_from.
— Иерархия целей + сроки + происхождение решения, а не только плоский набор тегов.
— Laya предлагает choice/score, умеет воздержаться; принятые метки имеют автора,
  версию модели, калибровку на RU/EN и ссылку на доказательство. Это пока спецификация.
— Идемпотентная маркировка новых/изменившихся spans, оценка precision/recall по
  пользовательской разметке, выборка спорных тегов для уточнения и обратимые исправления.
— Semantics/dependency retrieval объединяется с exhaustive ledger: найденное,
  исключённое и неизвестное сохраняются раздельно, без ложного «прочитано всё».

class Cancelled(Exception):
    pass

def checkpoint(cancel):
    if cancel():
        raise Cancelled('Отменено: завершённый результат не создан.')

def canonical(value):
    return json.dumps(value, ensure_ascii=True, sort_keys=True, separators=(',', ':'))

def identity(kind, *values):
    return kind + ':' + hashlib.sha256(canonical(values).encode('utf-8')).hexdigest()

def digest_file(path, cancel=lambda: False):
    with Path(path).open('rb') as source:
        digest = hashlib.sha256()
        while True:
            checkpoint(cancel)
            block = source.read(65536)
            if not block:
                return digest.hexdigest()
            digest.update(block)

def safe_path(root, relative):
    root = Path(root).resolve()
    p = (root / relative).resolve()
    if not p.is_relative_to(root) or p == root:
        raise ValueError('PATH_OUTSIDE_PACK: ' + str(relative))
    return p

def sanitize_tag(value):
    """Keep Unicode letters/digits; remove controls and syntactic punctuation."""
    text = unicodedata.normalize('NFKC', str(value)).casefold()
    return re.sub(r'[-_]+', '-', ''.join(c if c.isalnum() else '-' for c in text)).strip('-')

def label(facet, value, basis, status='SUGGESTED', confidence=None):
    if facet not in FACETS:
        raise ValueError('Unknown facet: ' + facet)
    item = {'facet': facet, 'value': str(value), 'tag': sanitize_tag(value),
            'status': status, 'basis': basis, 'confidence': confidence}
    return item

def jsonl(path):
    with Path(path).open(encoding='utf-8') as f:
        for n, line in enumerate(f, 1):
            if line.strip():
                try:
                    yield json.loads(line)
                except json.JSONDecodeError as e:
                    raise ValueError(f'INVALID_JSONL: {path}:{n}') from e

def write_row(out, row):
    out.write(canonical(row) + '\n')

def pieces(stream, chars):
    offset = 0
    while True:
        text = stream.read(chars)
        if not text:
            if offset == 0:
                yield 0, 0, ''
            return
        yield offset, offset + len(text), text
        offset += len(text)

def infer(text, path='', role=None):
    low = text.casefold()
    result = []
    rules = [('question', r'\?|\bвопрос\b'),
             ('goal_candidate', r'\b(?:хочу|нужно|цель|надо|want|need|goal)\b'),
             ('task_candidate', r'\b(?:todo|сделать|добавить|исправить|implement|fix)\b'),
             ('test_related', r'\b(?:pytest|unittest|assert|тест|тесты|test)\b'),
             ('web3_related', r'\b(?:flashloan|solidity|evm|web3|uniswap|arbitrage|флешлоан)\b'),
             ('decision_candidate', r'\b(?:решили|выбираем|decided|decision)\b')]
    for value, pattern in rules:
        if re.search(pattern, low):
            result.append(label('semantic_type', value, 'lexical_rule_v1'))
    suffix = Path(path).suffix.casefold()
    if suffix in {'.py', '.sol', '.js', '.ts', '.rs', '.go', '.cpp', '.java'}:
        result.append(label('semantic_type', 'code_candidate', 'filename_extension'))
    if re.search('[а-яё]', low):
        result.append(label('language', 'russian_present', 'unicode_script_heuristic'))
    if re.search('[a-z]', low):
        result.append(label('language', 'latin_present', 'unicode_script_heuristic'))
    if re.search(r'(?i)(private[_ -]?key|seed phrase|api[_ -]?key|пароль|секрет)', text):
        result.append(label('sensitivity', 'potential_secret_reference', 'lexical_rule_v1'))
    result.append(label('sensitivity', 'unclassified', 'no_complete_secret_or_pii_detector', 'UNKNOWN'))
    result.append(label('execution', 'source_data_untrusted', 'all_imported_content', 'ASSERTED'))
    result.append(label('status', 'unverified_content', 'no_fact_or_execution_verification', 'ASSERTED'))
    if role:
        result.append(label('authorship', role, 'exported_author_role_not_identity_verification', 'ASSERTED'))
    return result

def _metadata_labels(row, namespace, project, tags):
    output = [label('source', namespace, 'explicit_namespace_or_snapshot_source', 'ASSERTED'),
              label('machine_parse', row.get('text_state', 'UNKNOWN'), 'export_manifest', 'ASSERTED')]
    if project:
        output.append(label('project', project, 'explicit_cli_project', 'ASSERTED'))
    for tag in tags:
        output.append(label('custom', tag, 'explicit_cli_tag', 'ASSERTED'))
    annotation = row.get('annotation') or {}
    if annotation.get('tags'):
        # Original annotation stays intact; tokenization is only a suggestion.
        for tag in re.split(r'[,;\n]', annotation['tags']):
            if tag.strip():
                output.append(label('custom', tag.strip(), 'imported_annotation', 'ASSERTED'))
    return output

def _graph(labels_path, output, cancel=lambda: False):
    """Streaming graph file; edges refer to the same stable IDs as labels.jsonl."""
    with output.open('w', encoding='utf-8') as f:
        f.write('{"schema":"sce.label.graph.v1","nodes":[')
        first = True
        for record in jsonl(labels_path):
            checkpoint(cancel)
            if not first:
                f.write(',')
            first = False
            f.write(canonical({k: record[k] for k in ('id', 'kind', 'source_id', 'revision_id')}))
        f.write('],"edges":[')
        first = True
        for record in jsonl(labels_path):
            checkpoint(cancel)
            if record['kind'] == 'source':
                continue
            edge = {'from': record['id'], 'to': record['source_record_id'], 'relation': 'derived_from'}
            if not first:
                f.write(',')
            first = False
            f.write(canonical(edge))
            if record.get('parent_message_record_id'):
                f.write(',' + canonical({'from': record['id'], 'to': record['parent_message_record_id'],
                                        'relation': 'reply_to', 'target_may_be_absent': True}))
        f.write(']}\n')

def compare_revisions(old_labels, new_labels, destination):
    """Conservative dependency invalidation; graph/coverage are never proof of goal success."""
    def revisions(folder):
        path = Path(folder)
        manifest = json.loads((path / 'manifest.json').read_text(encoding='utf-8'))
        if digest_file(path / 'labels.jsonl') != manifest['labels_sha256']:
            raise ValueError('CORRUPT_LABELS')
        return manifest, {r['source_id']: r for r in jsonl(path / 'labels.jsonl') if r['kind'] == 'source'}
    old_manifest, old = revisions(old_labels)
    new_manifest, new = revisions(new_labels)
    changes = []
    for sid in sorted(set(old) | set(new)):
        a, b = old.get(sid), new.get(sid)
        state = 'ADDED' if not a else 'REMOVED' if not b else 'UNCHANGED' if a['revision_id'] == b['revision_id'] else 'CHANGED'
        annotations_changed = bool(a and b and a.get('annotation_revision_id') != b.get('annotation_revision_id'))
        changes.append({'source_id': sid, 'state': state,
                        'old_revision': a['revision_id'] if a else None,
                        'new_revision': b['revision_id'] if b else None,
                        'annotation_revision_changed': annotations_changed,
                        'old_annotation_revision': a.get('annotation_revision_id') if a else None,
                        'new_annotation_revision': b.get('annotation_revision_id') if b else None,
                        'invalidate_old_dependent_context': state in ('REMOVED', 'CHANGED') or annotations_changed})
    result = {'schema': 'sce.revision.diff.v1', 'changes': changes,
              'new_sources_require_context_reassembly': any(x['state'] == 'ADDED' for x in changes),
              'labels_artifact_changed': old_manifest['labels_sha256'] != new_manifest['labels_sha256'],
              'dependent_context_reassembly_required': old_manifest['labels_sha256'] != new_manifest['labels_sha256'],
              'reassembly_rule': 'Conservative: any labels artifact change includes tags, metadata, segmentation and derivative messages.',
              'duplicate_path_order_caveat': 'Reordering same-path duplicate entries changes occurrence identity.'}
    p = Path(destination)
    with p.open('x', encoding='utf-8') as out:
        json.dump(result, out, ensure_ascii=False, indent=2)
    return result

    b.add_argument('--span-chars', type=int, default=4096)

2. Процесс одной миссии

Нажать «Сказать цель» либо hotkey. Сохранить локально исходное audio, сегменты с временем, транскрипцию и исправления пользователя как разные версии. Постоянное прослушивание — отдельный включаемый режим с видимым индикатором, mute/stop и правилами хранения. Голос из видео, браузера и чужой цитаты не становится авторизацией команды.

Стабильные части транскрипта можно использовать для предварительного поиска. Исполнение изменяющих действий начинается после фиксации команды: иначе ASR может заменить «не запускай» на «запускай» или исправить число уже после действия. Кнопка STOP работает через независимый локальный канал, не ждёт ответа облачной модели. Все основные действия доступны клавиатурой/текстом/экранным диктором; голос не единственный способ остановки.

Создать mission.json: исходная цель, происхождение transcript, repository/base_commit, критерии приёмки, контекст с hash/path, разрешённые действия, бюджет времени/денег и требуемый режим web3. Секреты хранятся в локальном credential store; в документ попадают secret_ref, не значения. Предел ресурсов приостанавливает очередь и сохраняет остаток, не выкидывает источники.

Локальный Laya/правила выбирают одну из известных recipe: gather, inspect, test, propose patch, run known workflow, ask missing scope. Уверенность Laya — оценка классификатора, а не доказательство корректности/прибыльности. Для неизвестного маршрута предусмотрен abstain и более сильная модель/человек.

Context broker возвращает список использованных и ещё не прочитанных частей, цели, актуальные решения, противоречия, зависимости кода. Полная библиотека хранится локально; облачному провайдеру отправляется конкретный проверяемый пакет с provenance. Полный обзор репозитория проходит очередью всех частей с coverage ledger и отдельным обзором связей модулей; одно краткое summary не заменяет исходники.

Provider adapter вызывает Grok API и принимает structured proposal/tool calls. Для генерации кода достаточно patch + rationale + verification_plan. Исполняющий broker проверяет тип инструмента, аргументы, текущие grants, paths и ожидаемый state. Custom tool возвращает receipt: inputs_hash, started/finished, output_hashes, exit_code, фактический state. Проверить успех необходимо по результату инструмента, а не фразе Grok «done».

Для кода создаётся worktree от точного commit; patch проходит apply-check, разрешённые пути и review diff. Dependency install/scripts запускаются в отдельном ограниченном runner, если они входят в policy миссии; происхождение lockfile записывается. При ошибке теста разрешён bounded repair loop; каждый новый patch/head отменяет применимость предыдущего PASS. Артефакты тестов сохраняются даже при провале.

GitHub adapter создаёт/обновляет ветку и PR в заранее выбранном репозитории. Никакого прямого изменения main через текст из найденного документа. Права на push/PR/merge задаются при подключении; если merge заранее разрешён для данного класса задач, разрешение не нужно спрашивать каждый раз. Branch rules, exact head и нужные проверки всё равно обязательны. Модель не может расширить этот grant текстом в patch.

CI проверяет PR head и при необходимости merge candidate; фиксирует исходный head, base и протестированный merge SHA. После merge release job собирает именно итоговый merged commit, поскольку SHA squash/rebase может отличаться. Производится artifact + hash + подпись + provenance + capability manifest + schema migration plan.

Локальный updater обнаруживает только разрешённый release channel, проверяет identity/signature/hash/commit, сравнивает новые возможности и права, скачивает в staging. Нельзя обновлять исполняемые файлы работающего процесса «поверх» произвольным ZIP. Отдельный launcher/updater останавливает очередь в checkpoint, делает резервную копию базы, проверяет миграцию на копии, проводит healthcheck новой версии и атомарно переключает версию.

После запуска healthcheck должен доказать: библиотека открывается, число/хэши данных сохранены, поиск работает, очередь возобновляется, capabilities зарегистрированы и заявленные функции проходят smoke tests. При сбое возвращаются совместимые binary+DB snapshot; новые данные после миграции требуют журналирования/плана обратного переноса, поэтому откат базы не должен молча терять записи. Предыдущую исправную версию сохранять до завершения проверки.

3. Что действительно означает «само получает новые возможности»

Обновление может доставить новый handler, schema, UI и тест. Оно не выдаёт приложению доступ к новому Telegram-аккаунту, кошельку, приватному Drive, произвольной папке или admin-процессу. Capability diff различает: код доступен; учётная запись подключена; scopes выданы; credential валиден; handler протестирован. Новая возможность может показываться как AVAILABLE_NOT_CONFIGURED.

Существующие разрешения сохраняются при совместимом обновлении. Новый scope появляется в отдельном reviewable diff: зачем нужен, к каким данным относится, какие действия разрешает, как отозвать. Это не повторный запрос для уже разрешённого действия. Scope-политика хранится отдельно от обновляемого кода и не заменяется подписанным release manifest автоматически.

4. Параллельная работа без гонок

Планировщик исполняет DAG зависимостей, а не одновременно все шаги текста. Чтение независимых документов, HTTP read-only сбор, анализ модулей, независимые тестовые fixtures и генерация разных вариантов могут идти параллельно. Writes одной SQLite-базы, одной worktree/ветки, nonce одного signer, общий браузерный профиль/окно и foreground input требуют locks.

Locks: library_write, worktree:<id>, github_branch:<repo>:<branch>, browser_context:<id>, desktop_foreground, signer:<chain>:<address>. Статический анализ и тесты используют snapshot, поэтому их результаты не меняются от текущих правок пользователя. Несколько браузерных контекстов могут идти параллельно, если сайты/профили/сессии и полномочия допускают; sendKeys/мышь одного рабочего стола сериализуются. User activity приостанавливает foreground automation.

Read steps можно повторять после сетевой ошибки. Publish/merge/transaction/update нельзя вслепую повторять: сначала найти receipt по idempotency key и проверить итоговый state. UNKNOWN означает неизвестный результат, а не FAIL и не основание сделать действие второй раз.

5. Минимальная последовательность внедрения

Этап 1: mission schema, context manifest, read-only tools, evidence receipts, offline dry-run, сохраняемые состояния. Проверка на маленьком fixture и пользовательском 4 MB ZIP.
Этап 2: push-to-talk RU/EN ASR, preview/correction, route-known-workflow, локальные тесты в worktree, replay mission без облака.
Этап 3: Grok adapter → patch → тесты → draft PR. Provider credentials остаются локальными. Автоматический merge включается только в настроенной policy после реальной проверки exact-head/branch rules.
Этап 4: воспроизводимая Windows-сборка → подписанный update → staging/healthcheck/rollback. New scopes как отдельный permission diff.
Этап 5: web3 supervisor связывает qualification ledger со строго выбранным режимом. Наличие updater/голоса/Grok не повышает paper до live автоматически.

Это архитектурный вывод из возможностей источников и пользовательской цели. Ни один источник не обещает всю описанную end-to-end систему готовой из коробки.
