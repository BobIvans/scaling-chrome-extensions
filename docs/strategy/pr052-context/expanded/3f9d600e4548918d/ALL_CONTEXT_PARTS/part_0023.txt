адачи | Подключённые API с выбранным scope | Даты, timezone, draft/sent, entity links |
| Экран и браузер | Выбранные окно/вкладка, DOM/UIA, snapshot | Что действительно видно, какой target актуален |
| Web и X | Поиск или разрешённый API, сохранённые URLs | Автор, дата публикации, capture time, query coverage |

Хранение разделяется на originals, индекс и производные записи. Originals позволяют заново проверить вывод. FTS и метаданные дают быстрый поиск. Память содержит цели, предпочтения, решения, задачи и связи, каждая с ссылкой на исходный fragment. Embeddings добавляются при измеримом выигрыше retrieval; отдельная graph database для начала не нужна.

Минимальная запись источника: source_id, source_kind, origin, captured_at, content_hash, version, project_id, access_scope, coverage, parser_version и spans. Состояния покрытия: COMPLETE_FOR_DECLARED_SCOPE, PARTIAL, METADATA_ONLY, NOT_LOADED, ACCESS_GAP, PARSE_FAILED. COMPLETE относится к явно заданному scope, а не к целой жизни.

Память связывает Goal → Decision → Task → Function → PR → Receipt. Факт пользователя, наблюдение инструмента, гипотеза AI и проверенный outcome имеют разные типы. Каждое изменение сохраняет valid_from, valid_to и supersedes. При противоречии система показывает оба источника и ищет актуальное решение; свежесть сама по себе не делает утверждение истинным.

Практические команды: «вспомни наше решение по голосу», «покажи обещанное, но не сделанное», «продолжи SCE», «что изменилось после последнего PR», «собери документ по этой цели». Личные и рабочие namespaces позволяют давать AI ровно нужную часть. Команда «забудь» исключает запись и её производные индексы из дальнейшего поиска; ранее отправленные внешнему сервису копии нельзя отозвать локальным удалением.

## 6 Логика от запроса до выполненной задачи

Одна общая цепочка обслуживает текст, голос и выбранный объект на экране. ASR добавляет текст и сведения о происхождении; он не создаёт отдельную систему целей.

1. Capture сохраняет исходный запрос и выбранный объект. Финальная речь становится редактируемым текстом.
2. Intent compiler строит TaskSpec: результат, scope, ограничения, acceptance, бюджет и уже предоставленные полномочия.
3. Capability resolver проверяет зарегистрированные действия и доступные adapters.
4. Context compiler ищет evidence, расширяет найденные источники и отмечает конкретные gaps.
5. Если действие известно и входы достаточны, existing queue выполняет его. Если данных мало, возникает адресный запрос. Если функции нет, создаётся ТЗ.
6. AI возвращает plan/findings/patch proposal в связанном envelope. Ответ проверяется по schema, request, goal version и source revisions.
7. Executor выполняет зарегистрированные steps; verifier независимо наблюдает результат.
8. Receipt обновляет задачу и память. Новая цель или изменённый snapshot требует актуального binding.

Authority берётся из пользовательского поручения и действующих grants. Текст страницы, старого чата или модельный ответ остаётся данными. Низкорисковые действия в уже разрешённом scope продолжаются без повторных вопросов. Публикация, удаление, финансовый эффект и передача новых личных источников должны соответствовать конкретному разрешению пользователя.

При crash после потенциального эффекта задача переходит в NEEDS_RECONCILIATION. Сначала проверяем фактическое состояние, затем решаем, нужен ли retry. Лимиты attempts, времени, стоимости и отсутствие новых evidence останавливают цикл. Это позволяет продолжать работу автономно, не повторяя бесконечно одну ошибку.

## 7 Что отдавать ChatGPT Grok и любому другому AI

Переносимая единица — пакет задачи, не огромная сводка всей жизни. Каждый пакет содержит понятный человеку текст и machine manifest. Широкий архив доступен через индекс для дозагрузки.

| Выходной файл | Назначение |
| --- | --- |
| START_HERE_RU.txt | Что выполнить, актуальная цель, ограничения и ожидаемый ответ |
| TASK.json | Typed goal, scope, acceptance, authority reference, бюджет |
| CONTEXT.txt | Подобранные fragments с source IDs и точными диапазонами |
| MANIFEST.json | Версии, hashes, coverage, omissions и binding |
| NEXT_CONTEXT_REQUEST.json | Какие данные отсутствуют и зачем их получить |
| REVIEW_TEMPLATE.json | Формат ответа, findings, evidence refs, gaps, proposals |
| RESULT_RECEIPT.json | Actual observations и независимые проверки выполненного действия |
| REPORT.docx | Удобный итог для пользователя и обсуждения |

Это предлагаемый контракт будущего универсального compiler. В текущей реализации нужно сохранить existing V4/V5 handoff/import и сделать адаптер, а не молча заменить формат. Документ может запросить реализацию новой функции, но executable handler появляется после кода и проверок.

Документ для coding AI обязан включать current HEAD, существующих owners, touched files, зависимости, reproducer, acceptance и ограничения device verification. Репозиторий мог измениться после экспорта: import обязан обнаружить staleness.

Ни один документ не гарантирует, что AI «понимает всё». Качество проверяется задачами: может ли AI восстановить решения, показать доказательства, назвать пробелы и дать исполнимый следующий шаг. Большой архив сохраняем вне model context; загружаем нужные источники по запросу. Такой подход соответствует context engineering с выборочным retrieval и сохранением внешней памяти. [R1]

## 8 Модель независимого слоя

Рекомендуемая архитектура: один SCE store и execution owner; поверх него универсальный task/context API; по краям adapters AI и источников. Laya, если её установленный API полезен, работает как advisory router. Название продукта может быть Laya, но технически не должно появляться два владельца состояния.

Начальный общий интерфейс: search_context, read_source, build_task_packet, propose_plan, get_task_status, request_context, enqueue_registered_action и read_receipt. Read и write tools публикуются раздельно. К каждому tool относятся schema, capability, версия и независимый verifier.

MCP подходит для доступа к ресурсам и typed tools; стандарт не означает, что любой AI клиент поддерживает каждый инструмент или имеет доступ к ПК. Для каждого клиента нужен capability profile и проверка совместимости. OpenAI документирует remote MCP и фильтрацию allowed_tools; поэтому модели показываем только нужные инструменты задачи. [R2–R4]

Три способа подключения: переносимый TXT/JSON через ручной export/import; официальный API adapter; поддерживаемый клиентом MCP/plugin. Первый вариант даёт быстрый старт без платных вызовов. API расходы считаются отдельно; отсутствие adapter не выдаётся за скрытый доступ к сервису.

Router выбирает по измеренной успешности нужного типа задач, цене, задержке и требованиям к данным. Дополнительный критик включается только для конкретного unresolved вопроса. Совпадение двух ответов не доказывает истину. Новые задачи можно сравнивать на одинаковом benchmark, затем закреплять удачный маршрут.

## 10 Критерии ближайших изменений

Для SCE-NEXT-02 входом служит реальный JS module выбранного checkout, например goal-normalizer.mjs. Результат — выбранные statically resolved imports и явные gaps. Приёмка должна включать re-export, циклы, отсутствие файла, dynamic import, aliases и изменение зависимого source. AST closure не равна полному runtime call graph.

Для SCE-NEXT-03 берём один доступный экспорт чатов и одну папку документов. Повторный импорт не удваивает сообщения; interrupted import продолжается с checkpoint; один изменённый документ создаёт новую version. Панель показывает, какие вложения реально прочитаны. Объявлять «все 100 чатов загружены» можно только с инвентарём этих 100 источников и отчётом покрытия.

Для SCE-NEXT-04 один запрос создаёт одновременно TXT, DOCX и manifest из общего snapshot. Приёмка: одинаковые goal/scope/source IDs во всех выходах, присутствующие omissions, целый выходной файл и отклонение ответа для другой task. DOCX должен быть читаемым; byte receipt подтверждает сохранение, а содержательная проверка — соответствие acceptance.

Для SCE-NEXT-06 тестовые случаи включают смену цели, старую отменённую идею, противоречащие сведения, слова ассистента «реализовано» без receipt и фактически merged PR. Ответы «что решено» и «что сделано» должны показывать разные типы evidence.

Для SCE-NEXT-07 ложные SUCCESS проверяем намеренно: exit 0 без файла, частичный файл, неправильное содержимое, stale target, отсутствие CI на нужном head, crash после эффекта и поздний результат после STOP. Общий verifier выбирается по effect type, не по оценке самого исполнителя.

Для SCE-NEXT-10 выбираем один редактор и конкретный документ на Windows. UIA/DOM выделяют target; сохранённый файл прочитывается независимо. Microsoft UI Automation даёт структурированный доступ к элементам Windows; DOM locators по roles/labels помогают искать элементы браузера. Применимость к конкретному приложению подтверждается device canary. [R5–R6]

## 11 Голос и контекст ПК

Сначала push-to-talk: записать → local ASR → финальный текст → правка → общий TaskSpec. На Dell используем один ASR worker и ограничиваем параллельную нагрузку. faster-whisper поддерживает CPU INT8; его upstream benchmark не предсказывает latency на нашем устройстве. Измеряем фактический p50/p95 и RAM. [R7]

Обязательные речевые кейсы: отрицания «не отправляй», числа и даты, RU/EN, названия репозиториев, пауза внутри фразы, пустая речь, исправление команды и STOP. Partial transcript не запускает действие; устаревший transcript после отмены не возвращает старую цель.

Команда «сделай это» использует выбранный объект: окно, вкладку, файл или текст. Контекст содержит target identity и время snapshot. Перед действием проверяем актуальность target. Пример: «собери по этому репозиторию документ и сохрани в мою папку» → выбранный checkout → context packet → document compiler → file verifier.

Длительная запись экрана всей жизни даёт большой шум и затраты. Более полезен режим событий: активная задача, выбранное окно, завершение действия, новый файл или CI. OCR дополняет недоступную структуру; он не подтверждает эффект сам по себе. Always listening и wake word остаются поздним экспериментом после устойчивого push-to-talk.

Доступность входит в общий интерфейс: клавиатурная навигация, большие controls, озвучивание статуса, повтор последнего сообщения и короткая команда остановки. Успех с конкретной речью и устройством измеряем, а не обещаем для любых условий.

## 12 Как получить наибольшую отдачу

Сначала измеряем ручной baseline на повторяющихся задачах: восстановить решение, найти missing feature, подготовить ТЗ, собрать документ, прочитать CI blocker, продолжить workflow. Затем сравниваем тот же набор с приложением. Считать следует все failed attempts, исправления и setup, а не только удачный запуск.

Чистая экономия времени за период = время ручного baseline − время пользователя с приложением − время исправлений − доля затрат на настройку и обслуживание. Стоимость проверенной задачи = все API и инфраструктурные затраты периода / число verified outcomes. Если времени мало и цена велика, красивый «автономный» pipeline может иметь отрицательную отдачу.

| Метрика | Как считать |
| --- | --- |
| Verified completion rate | Достигнуты acceptance / все начатые задачи выбранного набора |
| False success rate | SUCCESS без независимого результата / все SUCCESS |
| Correction burden | Минуты ручной коррекции на запуск |
| Context quality | Recall нужных evidence и верная attribution |
| Cost per outcome | Включает неуспехи, retries и critic calls |
| Open loop closure | Закрытые старые задачи с receipt за неделю |

Набор из 30 замороженных кейсов: 10 на память, 10 на документы/код и 10 на зарегистрированные действия. Меняем один фактор: FTS/embeddings, minimal/full context, rules/Laya, один AI/critic. До замера не назначаем произвольные проценты прироста.

Начальный gate для конкретной версии: на этих 30 кейсах нет ложного SUCCESS; время и cost не ухудшились против baseline; все UNKNOWN видны. Размер выборки ограничивает вывод: этот gate не доказывает универсальную надёжность. Реальные device tasks не заменяются fixtures.

Наибольшая ожидаемая отдача: избавить тебя от повторного объяснения проекта, ручного объединения ZIP и потери незакрытых задач. Автоматизация очередного уже понятного действия становится следующим источником экономии. Массовые debates моделей, непрерывный screen recording и marketplace сотен skills имеет смысл добавлять после этих измерений.

## 13 Новые эксперименты для усиления интеллекта

Ниже наши продуктовые гипотезы. Они предложены для экспериментов и не считаются уже реализованными или доказанно более умными.

**Контекст который меняет решение.** На замороженной задаче удалять по одному fragment из пакета и проверять изменение качества. Так находим минимальный evidence set, уменьшаем цену и выявляем пропущенную зависимость. Originals остаются доступными; сжатие не уничтожает источник.

**Память с проверкой возражений.** По команде «что может сделать этот план неверным» находить отменённые решения, отрицательные results и свежие изменения sources. Проверка полезна против повторения старой ошибки. Метрика — обнаруженные реальные conflicts, а не число критических замечаний.

**Радар забытых обещаний.** Сопоставлять фразы «добавим», «готово» и TODO из чатов с current functions, PR и receipts. Missing/partial получает task card. Verified receipt закрывает обещание. Это должно сокращать open loops без генерации повторных PR.

**Лаборатория новых функций.** X/web signal создаёт evidence-backed hypothesis, маленький reproducer и comparison case. Если новая технология не улучшает outcome при том же бюджете, её не интегрируем. X Search у xAI поддерживает фильтры accounts и дат; это инструмент получения кандидатов, не доказательство их полезности. [R8]

**Планировщик ценности следующего шага.** Выбирать действие по ожидаемой экономии, наличию входов, цене проверки и blocker dependencies. Сначала показывать качественное объяснение выбора. Числовую модель обучать на actual task history, не на выдуманной вероятности успеха.

**Проверка навыка на изменениях.** Для записанного workflow менять имена файлов, порядок controls и start state. Сценарий становится зарегистрированным skill, когда успешно проходит canary и независимую проверку на held-out inputs. При drift создаётся repair task для owner.

**Сон до новых данных.** Не крутить LLM каждые несколько секунд. Trigger срабатывает на новый источник, изменение CI или исчезновение blocker. Durable supervisor продолжает с checkpoint в существующей очереди. Измеряем сэкономленные calls и задержку реакции.

**Дневник экспериментов.** Каждая идея связывается с гипотезой, фиксированным набором входов, baseline, результатом и решением продолжить/отклонить. AI получает и успешные, и отрицательные результаты. Это постепенно улучшает реальные решения без обещания «гениальности» от одного prompt.

## 15 Задание будущему coding AI

Начни с актуального SCE HEAD и existing owner inventory. Прочитай этот план и NEXT_FUNCTIONS_RU.json. Выбери одну задачу по реальному blocker и доступным входам; сохрани уже существующие изменения. Не переносить весь Studious и не создавать вторые SQLite, queue или Native Host.

Для code задачи создай небольшой diff, reproducer и meaningful focused checks. Для device задачи получи наблюдения на выбранном устройстве; когда устройство недоступно, запиши NOT_RUN и точный next-context request. Не закрывай функцию по одному mock, JSON schema или словам модели.

Верни goal/task binding, base и final tree/head, changed owners, actual outputs, проверенные acceptance, failures, remaining gaps и следующий шаг. Быстрые структурированные решения в агентах

Дешёвый и быстрый pre-filter перед тяжёлыми моделями

    def work(self, action):
        if self.busy:
            messagebox.showinfo('Задание выполняется', 'Дождитесь завершения или нажмите STOP.')
            return
        self.busy = True
        self.cancel.clear()
        self.status.config(text='Выполняется…')
        def run():
            s = None
            try:
                s = Store(self.library)
                def progress(text):
                    # Coalesce progress to avoid unbounded UI messages.
                    self.last_progress = text
                result = action(s, progress, self.cancel.is_set)
                self.events.put(('done', str(result)))
            except Exception as e:
                self.events.put(('error', str(e)))
            finally:
                if s:
                    s.close()
        self.last_progress = ''
        threading.Thread(target=run, daemon=False).start()

    def poll(self):
        if self.busy and getattr(self, 'last_progress', ''):
            self.status.config(text=self.last_progress)
        try:
            while True:
                kind, result = self.events.get_nowait()
                self.busy = False
                self.status.config(text=('Ошибка: ' if kind == 'error' else 'Готово: ') + result[:500])
                self.refresh_snapshots()
                if kind == 'error':
                    messagebox.showerror('Операция не завершена', result)
        except queue.Empty:
            pass
        self.root.after(100, self.poll)

    def refresh_snapshots(self):
        self.snapshots = self.store.snapshots()
        self.snap['values'] = [f'{x["created"]} | {x["state"]} | {x["source"]} | {x["id"][:8]}' for x in self.snapshots]
        if self.snapshots:
            self.snap.current(0)
            self.choose_snapshot()

    def choose_snapshot(self, event=None):
        if self.snap.current() < 0:
            return
        self.sid = self.snapshots[self.snap.current()]['id']
        self.offset = 0
        self.refresh_entries()

    def refresh_entries(self):
        if not self.sid:
            return
        try:
            total, rows = self.store.entries(self.sid, self.offset, self.page_size, self.query.get())
            self.tree.delete(*self.tree.get_children())
            self.rows = {str(r['id']):r for r in rows}
            for r in rows:
                self.tree.insert('', 'end', iid=str(r['id']), values=(r['path'],r['text_state'],r['size']))
            self.total = total
            self.count.config(text=f'{self.offset + (1 if rows else 0)}–{self.offset+len(rows)} / {total}')
        except Exception as e:
            messagebox.showerror('Поиск', str(e))

    def search(self):
        self.offset = 0
        self.refresh_entries()

    def page(self, delta):
        next_offset = self.offset + delta * self.page_size
        if 0 <= next_offset < getattr(self,'total',0):
            self.offset = next_offset
            self.refresh_entries()

    def select_entry(self, event=None):
        selected = self.tree.selection()
        if not selected:
            return
        self.entry, self.seq = int(selected[0]), 0
        row = self.store.db.execute('SELECT tags,note FROM annotations WHERE entry=?', (self.entry,)).fetchone()
        for widget, value in [(self.tags,row['tags'] if row else ''),(self.note,row['note'] if row else '')]:
            widget.delete(0,'end')
            widget.insert(0,value)
        self.render_text()

    def render_text(self):
        if not self.entry:
            return
        text, self.text_total = self.store.text_page(self.entry,self.seq)
        row = self.store.db.execute('SELECT * FROM entries WHERE id=?',(self.entry,)).fetchone()
        self.preview.config(state='normal')
        self.preview.delete('1.0','end')
        self.preview.insert('1.0', json.dumps(dict(row),ensure_ascii=True,indent=2)+'\n\n'+text)
        self.preview.config(state='disabled')
        self.text_count.config(text=f'Страница {self.seq+1 if self.text_total else 0}/{self.text_total} — весь текст в экспорте')

    def text_page(self, delta):
        if 0 <= self.seq+delta < getattr(self,'text_total',0):
            self.seq += delta
            self.render_text()

    def import_files(self):
        paths = filedialog.askopenfilenames(title='Выберите ZIP или любые файлы')
        if paths:
            def action(s,p,c):
                results=[]
                for path in paths:
                    if c(): break
                    results.append(s.import_source(path,p,c))
                return ', '.join(results)
            self.work(action)

    def import_folder(self):
        path = filedialog.askdirectory(title='Репозиторий или папка документов')
        if path:
            self.work(lambda s,p,c:s.import_source(path,p,c))

    def resume(self):
        sid = self.sid
        if sid:
            self.work(lambda s,p,c:s.import_source('.',p,c,resume=sid))

    def export(self):
        if not self.sid:
            return
        parent = filedialog.askdirectory(title='Куда сохранить новый context pack?')
        if not parent:
            return
        size = simpledialog.askinteger('Размер TXT-части','Байт на часть (не токены):',initialvalue=200000,minvalue=4)
        if not size:
            return
        sid = self.sid
        import datetime
        dest = Path(parent) / ('context_'+sid[:8]+'_'+datetime.datetime.now().strftime('%Y%m%d_%H%M%S_%f'))
        def action(s,p,c):
            index=s.export(sid,dest,size,p,c)
            return f'{dest} — {index["entries"]} записей, {len(index["parts"])} TXT'
        self.work(action)

    def parse_chat(self):
        entry = self.entry
        if entry:

    def annotate(self):
        if self.entry and not self.busy:
            self.store.annotate(self.entry,self.tags.get(),self.note.get())
            self.status.config(text='Теги и заметка сохранены.')

    def project_path(self):
        if not self.sid:
            return None
        snapshot = self.store.db.execute('SELECT * FROM snapshots WHERE id=?',(self.sid,)).fetchone()
        if snapshot['kind'] != 'folder':
            messagebox.showinfo('Проект','Для терминала/VS Code выберите snapshot локальной папки. ZIP не исполняется и не распаковывается в проект.')
            return None
        p = Path(snapshot['source'])
        if not p.is_dir():
            raise ValueError('Исходная папка больше не существует.')
        return p

    def vscode(self):
        try:
            path = self.project_path()
            if not path: return
            # Launch real Code.exe instead of passing untrusted paths through code.cmd.

            exe = next((str(p) for p in candidates if p.is_file()),None)
            if not exe:
                exe=filedialog.askopenfilename(title='Выберите исполняемый файл VS Code',filetypes=[('Executable','*.exe'),('All','*')])
            if exe:
                subprocess.Popen([exe,'--new-window',str(path)],shell=False)
        except Exception as e: messagebox.showerror('VS Code',str(e))

    def terminal(self):
        try:
            path = self.project_path()
            if not path: return
            if os.name != 'nt': raise ValueError('Эта кнопка предназначена для Windows PowerShell.')
            exe = shutil.which('powershell.exe')
            if not exe: raise ValueError('PowerShell не найден.')
            subprocess.Popen([exe,'-NoProfile','-NoExit'],cwd=path,shell=False,creationflags=subprocess.CREATE_NEW_CONSOLE)
        except Exception as e: messagebox.showerror('PowerShell',str(e))
