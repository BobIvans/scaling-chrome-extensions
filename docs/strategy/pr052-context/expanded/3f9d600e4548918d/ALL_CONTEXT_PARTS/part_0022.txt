# Агрегатор контекста и проверяемая автоматизация SCE
Рабочий план для BobIvans и AI разработчика
3 октября 2026 года

## 1 Главное решение

Развиваем SCE как постоянный слой между моими данными, задачами, компьютером и разными AI. Приложение хранит контекст и состояние выполнения; ChatGPT, Grok, Claude, локальная модель и Laya подключаются как сменяемые компоненты. Пользователь формулирует запрос текстом или голосом, система собирает относящиеся к нему источники, создаёт документ для AI, принимает структурированный ответ и выполняет доступный сценарий с проверкой результата.

Наибольшую ожидаемую отдачу сейчас дают завершённые цепочки: восстановить решение из старых чатов; создать точное ТЗ; продолжить разработку на актуальном коде; получить проверенный документ; повторить уже освоенный сценарий на ПК. В этом плане 16 задач. Их ID обозначают backlog, а не созданные GitHub PR.

«Автоматизировать что угодно» означает постепенно расширять набор поддержанных источников, приложений и проверяемых навыков. Новый неизвестный сценарий сначала становится конкретным заданием на разработку. Уровень агента оцениваем успешными задачами, временем и стоимостью. Оснований объявлять приложение самым сильным агентом среди всех существующих пока нет.

## 4 Что полезного перенести из Studious

Да, Studious содержит функции и подходы, которые полезны SCE. Переносить стоит проверенную логику и контракты, адаптируя их к текущим владельцам SCE. Торговые routes, wallet/sign/send и market runtime остаются в Studious. SCE вызывает ограниченный квалификационный интерфейс и управляет контекстом, задачами и UI.

| Studious файл и функция | Польза для SCE |
| --- | --- |
| qualification_report.py _semantic_reason | Проверять смысл результата каждого действия, а не только exit code |
| qualification_report.py _checkpoint и _verify_completed_run | Запоминать завершённые этапы и проверять artifacts перед replay |
| fast_q_automation.py _inspect_blocker _owner_for _prepare_repair | Blocker → owner → точное repair ТЗ; отсутствие внешних данных не лечить выдуманным patch |
| occ_memory_qualification_bridge.py _verify_replay | Связывать request и profile; reconcile до retry при неизвестном эффекте |
| occ_durable_library.py verify_current_version и history | Проверять lineage и актуальность источника |
| qualification_pr186.py source_tree_identity и verify_signed_verdict | Различать integrity hash и evidence от аутентифицированного производителя |

Эти функции найдены в исходниках указанного Studious snapshot. Полная production readiness Studious этой проверкой не устанавливалась. SCE уже владеет своей SQLite и очередью: вторую базу, Native Host и конкурирующий worker создавать не нужно. Для первого переноса достаточно общего интерфейса postcondition checker и таблицы blocker → owner. [C3]

## 5 Как приложение агрегирует контекст моей жизни

Система начинает с инвентаря реально подключённых источников. Для каждого источника сохраняет вид доступа, диапазон дат, последнюю синхронизацию и покрытие. «Все данные» определяется выбранными папками, экспортами и подключёнными аккаунтами. Невидимый архив, закрытый аккаунт или не загруженное вложение должны быть заметным пробелом.

| Источник | Как получать | Что учитывать |
| --- | --- | --- |
| Чаты AI | Официальные экспорты и доступные connectors; выбранная вкладка | Roles, message IDs, branches, вложения, полный export или только DOM |
| Telegram и voice notes | Доступный export/API и выбранные записи | Message IDs, reply/thread, audio hash и transcript version |
| Документы и папки ПК | Выбранные roots, file watcher, import | Raw hash, parser version, изменённый или удалённый файл |
| Git и GitHub | Checkout плюс разрешённый API | Commit/tree, dirty files, PR state, CI на точном head |
| Почта календарь з
