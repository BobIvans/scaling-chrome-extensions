## Уже есть полезный фундамент

`repo_context` уже привязывает записи к Git-объектам, хранит entries/chunks, состояние обхода и byte offsets. `automation_core` уже имеет SQLite owner, версии источников, задачи, lease, checkpoint и события. `context_review` отличает review-утверждение от подтверждённого результата. Это нужно расширять, а не обходить вторым production-хранилищем. [G03–G05]

`agent-bridge/QUALIFICATION_ADAPTER_RU.md` описывает прямой вызов CLI без Chrome. Следовательно, переносить надо транспорт/UI и политику capabilities, а не переписывать существующую qualification-логику. [G07]

## Статические сигналы и настоящие дефекты

`except: pass`, длинная функция, TODO или одинаковые имена не доказывают ошибку. Для каждого сигнала нужен путь, SHA, line range, ожидаемое поведение, минимальный тест, фактический результат и версия среды. Отдельно классифицировать `CODE_DEFECT`, `MISSING_EVIDENCE`, `ENVIRONMENT_BLOCKER`, `PROPOSAL_ONLY`. Старый PR или красивый markdown не меняют status автоматически.

## Чего эта проверка не установила

Полное число файлов/функций, точное покрытие всей кодовой базы, статус всех PR/CI, содержимое недоступных старых ZIP, работоспособность на твоём Dell и прибыльность бота здесь не установлены. Инструмент полного локального сбора приложен именно для закрытия этих пробелов без выдумывания totals.
