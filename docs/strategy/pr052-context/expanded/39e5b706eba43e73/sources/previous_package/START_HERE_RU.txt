Контекст и цель
Развиваем BobIvans/scaling-chrome-extensions как постоянный слой контекста, задач и проверяемых действий для разных AI. Путь: текст/финальный голос → TaskSpec → подключённые источники → context packet → AI proposal → registered action → independent verifier → receipt → память.
SCE владеет canonical SQLite, очередью и Native Host. Studious хранит предметный bot runtime; использовать его semantic checks, checkpoints, blocker-to-owner mappings и bounded qualification bridge, а не переносить весь репозиторий.

К началу разработки обязательно получить актуальные HEAD, changes и owner inventory.

Как использовать с AI
Передай DOCX или TXT и JSON. Попроси выбрать одну задачу по текущему blocker, прочитать relevant owners и запросить только реально отсутствующий контекст. Для реализации добавь актуальный checkout или соответствующий V4/V5 handoff; этот обзор не содержит весь код обоих репозиториев.
Первый code candidate — SCE-NEXT-02, static JS/TS dependency closure. Первый device candidate — SCE-NEXT-01, installed Chrome → bound review → verified report.

Требования к ответу coding AI
Указать выбранный task ID, актуальную базу, owners, diff, проверки, реальные output observations, failures, remaining gaps и следующий шаг.
Не считать claim DONE, валидный JSON, mock, exit 0 или число PR доказательством выполненной задачи.
Не создавать вторую SQLite/очередь/Native Host. Не переименовывать task IDs в несуществующие номера PR.
ASR, UIA, установленный Chrome и Laya inference требуют actual device evidence; при его отсутствии NOT_RUN.
Пакет — план разработки. Он не запускает automations и не разрешает финансовое/live execution, публикацию или передачу новых личных данных.

Что действительно восстановлено
Найден полный сохранённый текст с 38 группами функций Laya и обсуждением X.com. Точное название исходного голосового чата не установлено. Доступна поисковая история связанных обсуждений, не полный архив всей жизни или всех 100 чатов.
