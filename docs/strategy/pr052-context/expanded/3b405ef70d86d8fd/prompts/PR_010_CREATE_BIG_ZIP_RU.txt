- Проекция воспроизводится из тех же events/evidence детерминированно; её UI-переключатель не обходит policy.
LAYA4-004 — Полный ledger форматов, gaps и защищённых данных
- Для каждого entry есть одна disposition: indexed, excluded, unsupported, missing, error, deferred или pending; pending исключает completion.
- LFS pointer отличается от available payload; submodule/symlink metadata не выдаются за содержимое target.
- Binary/non-UTF8, oversize, parse error, credential heuristic и operator exclusion сохраняют reason и исходный hash, когда он доступен.
- Zero omission проверяет accounted==tracked_total; all_tracked_bytes_exportable имеет отдельное значение.
- Exclusion policy не запрещает обычные исходники по случайной подстроке; секретные bytes не дублируются в diagnostic log.
LAYA4-013 — Добавить каталог источников с intent и lifetime policy
- Record отделяет raw/extracted/transcript/summary/claim/evidence и имеет стабильные source/revision IDs.
- Сохраняются original user text, capture intent, source_event_at и captured_at; неизвестное время не выдумывается.
- Project/lifetime scope и share/retention policy закреплены отдельно от auto labels.
- Namespace/profile границы существующего store применяются ко всем каталожным queries.
- Импорт одного материала не делает его автоматически доступным всем future automations.
LAYA4-014 — Организовать extractor очередь и gap reconciliation
- Каждый extractor имеет format/version/limits и pure input→derived output contract; output ссылается на raw hash/ranges.
- Existing ChatGPT export/selected record paths используются повторно; raw transcript и исправленный текст не смешиваются.
- PDF/OCR/ASR/image/unsupported inputs имеют явное состояние READY/PENDING/UNSUPPORTED/FAILED/MISSING.
- Bulk import resumable и идемпотентен; network/model invocation обозначен capability и scope, не происходит скрытно.
- Неизвестный attachment учитывается до извлечения; OCR/ASR confidence не объявляется доказанным содержимым.
LAYA4-015 — Автоматические метки с источником и user overlay
- Label хранит dimension/value/source_ref/extractor_version/assigned_at/evidence class.
- Детерминированный path match, keyword rule, AI inference и user label различаются.
- User overlay имеет приоритет и сохраняется после reindex; конфликт виден и откатывается.
- Dimensions включают project/topic/goal/module/capability candidate/evidence/freshness/delivery/next action.
- Implemented/enabled/usable выводятся из evidence owner; слова из исходного чата не устанавливают их напрямую.
LAYA4-016 — Единый поиск, фильтры и timeline с source links
- Namespace/project-aware current search использует existing Core search owner; legacy item shapes не приводят к KeyError/потере результата.
- Есть exact ID/path/quote, FTS, project/type/topic/date/status filters и version selector.
- Каждый hit показывает excerpt, origin, revision/freshness и основание попадания.
- Timeline отличает source_event_at от captured_at и не размещает unknown event time как точную дату.
- Пагинация стабильна; private project фильтр применяется до поиска/reranking, не только после выдачи.
ACTION5-04 — CaptureEnvelope сохраняет исходный текст и автора
- Реконструкция raw text совпадает byte-for-byte; нормализованный search text хранит обратные offsets.
- Время сообщения, время захвата и inferred event time не объединяются в одно поле.
- Цитата другого автора внутри сообщения не становится словами пользователя; неизвестное авторство явно UNKNOWN.
- Исправление пользователя создаёт overlay/version, сохраняя исходное написание.
ACTION5-05 — Учитывать full-scroll чат и недоступные ветви
- Top/middle/bottom и virtualized-history fixtures дают по одной source version на наблюдаемый message ID.
- Loading/end-of-history подтверждается наблюдением; scroll без новых сообщений сам по себе не означает COMPLETE.
- Недоступная ветвь, удалённое сообщение, вложение и login wall отображаются как конкретный gap.
- Export и DOM capture связываются по происхождению; разные ветви не склеиваются по похожему тексту.
ACTION5-06 — Закрепить общий контракт файлового импортера
- Несовпадение extension/MIME отражается в manifest; extraction не скрывает оригинал.
- У каждого выбранного файла ровно один исход: imported, excluded с причиной, unsupported или error.
- Повторное продолжение создаёт новые версии только для изменённых bytes и сохраняет все origins.
- Unknown importer fields сохраняются в raw envelope, не становятся исполнимыми настройками.
ACTION5-09 — Учитывать архивы, папки и вложения как граф происхождения
- Вложенные ZIP, одинаковые bytes в двух путях, empty entry и missing attachment учтены отдельно по происхождению.
- Traversal path, symlink, compression bomb и budget limit дают явный blocked/error и не записывают вне staging scope.
- Repo LFS pointers/submodules остаются отдельным disposition до фактического получения разрешённых bytes.
- Повторная распаковка не считает копии независимыми подтверждениями.
ACTION5-10 — Версионировать автометки и пользовательские исправления
- Каждый автоматический tag указывает rule/model version и supporting source span либо отмечен inference.
- User correction имеет приоритет в представлении и не удаляет прежнее предложение.
- Разные facets не объединяют source type, цель, статус исполнения и private scope в одну метку.
- Taxonomy upgrade не переименовывает исторические labels без version mapping.
ACTION5-11 — Сделать SourceAddress для точной цитаты и диапазона

- Ошибочные range bounds, namespace и hash отклоняются до чтения.
- Удалённый оригинал возвращает tombstone/missing и не подменяется совпадающей цитатой.
