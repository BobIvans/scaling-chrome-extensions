# Расписание и ресурсы

ScheduleSpec: stable schedule_id, revision, active/pause state, IANA timezone, local trigger/window, gap_policy, fold_policy, catch_up, window/deadline, registered template+version, scope/grant hash, budget account и max catch-up occurrences. Occurrence identity: SHA256 canonical JSON [schedule_id, revision, resolved UTC instant, logical slot ID]. Внутри revision UTC instant уникален; разные fold occurrences различаются UTC. Не использовать local time без offset/fold.

Default proposal для согласования продукта: gap=SKIP; fold=FIRST; catch-up=LATEST. Все значения сохраняются явно, без silent default при миграции старого расписания. Допустимы gap SKIP/SHIFT_FORWARD; fold FIRST/SECOND/BOTH; catch-up SKIP/LATEST/BOUNDED. SHIFT_FORWARD добавляет размер DST gap к local slot. Historical schedule edits не переименовывают old occurrences. Обработка old queued jobs при edit: SUPERSEDE_UNSTARTED, RUNNING_KEEP_PINNED; при scope/policy revoke — cancel/reconcile по действующим правилам.

Для Europe/Riga 2026-03-29 local 03:30 отсутствует; 2026-10-25 local 03:30 имеет две UTC версии. BOUNDED выбирает ограниченное число chronological slots в catch-up window и сохраняет missed/skipped ledger для остальных. LATEST оставляет один последний допустимый slot; без сети/квоты occurrence может waiting, не пропадать. При backward clock курсор не отматывается; monotonic durations действуют в одном boot, cross-boot deadline — durable UTC + reconciliation clock context.

CanonicalResource: logical ID, physical identity where available, volume/file identity или repo common-dir identity, alias evidence, read/write scope и UNKNOWN marker. Windows fixture проверяет C:\x, c:/x, junction/symlink/UNC alias по actual physical identity. UI focus/clipboard/session — общий ресурс, даже если conversations разные. Integration write set отдельно от execution write set. Capital resources только интерфейс для №20, здесь live торговля не запускается.

Admission decision атомарно фиксирует limit profile revision, baseline, observed capacity, reservations и reason. Free slots не обходят Core max_parallel. Unknown resource cost допускает conservative registered estimate либо blocker, никогда автоматический ноль. Disk pressure ограничивает staging/queue: сохраняет deferred job и corpus refs, не молча пропускает файлы. STOP и reconciliation приоритетны, затем interactive, background с aging. Тест starvation проверяет bounded waiting при конечном потоке higher-priority задач.
