WS-013 — Единый AI-пакет: task/result, WHY_THIS_PACKET, NEED_CONTEXT и share projection
Scope:
- Provider-neutral immutable task document и проверяемый result contract
- Selection basket, WHY_THIS_PACKET, share/redaction preview
- Все части, exact range NEED_CONTEXT, typed read-only library gateway
Граница: Переиспользовать существующие handoff/review/manifest/export owners. Реальные provider/API/CLI/UI adapters имеют независимую qualification; их лимиты не задают лимит архива.
Приёмка:
- Preview и export имеют один digest
- Любой обязательный source вне текущей части остаётся в manifest
- Ответ связан с task/packet/criterion revision
- Supplied/read/used не смешиваются
- Ручной roundtrip работает до подключения UI automation
- Повтор/restart/cancel/source drift имеют отдельные фактические исходы.
- Проверена совместимость с предоставляющими и потребляющими пакетами.
- Каждый незакрытый source criterion сохранён с owner и next evidence; package validation не считается runtime test.

WS-014 — Backup, restore, миграции, retention и опциональная синхронизация
Scope:
- Согласованные DB/blob/event backups и проверка восстановления
- Tombstones/retention/derived cleanup и conflicts
- Portable snapshot sync с явными namespaces и rehearsal миграций
Граница: Это жизненный цикл данных. Переключение исполняемого release и canary — №33. Опциональный sync не должен требоваться для локальной работы.
Приёмка:
- Restore сравнивает hashes/heads/overlays/relations
- Повреждённый или неполный backup не активируется
- Старый backup не resurrect удалённые current sources
- Два профиля не становятся competing writers
- Каждая migration/rollback проверена на копии
- Повтор/restart/cancel/source drift имеют отдельные фактические исходы.
- Проверена совместимость с предоставляющими и потребляющими пакетами.
- Каждый незакрытый source criterion сохранён с owner и next evidence; package validation не считается runtime test.

WS-015 — Долговременная память: поиск по времени, версиям и большим корпусам
Scope:
- Goal-directed retrieval с exact ranges и temporal applicability
- Frozen relevance corpus, hard negatives и conflicting versions
- Объяснение выбора контекста и bounded retrieval из растущего архива
Граница: №10 реализует базовый поиск; №24 квалифицирует lifetime retrieval. Расширяемый corpus не означает, что один AI-запрос прочитал все данные.
Приёмка:
- На собственных вопросах возвращается нужная версия источника
- Устаревшее и противоречивое не сливается в один факт
- Manual corrections сохраняются
- Cold/warm latency и RAM имеют corpus denominator
- Missing evidence вызывает точный запрос, а не выдуманный ответ
- Повтор/restart/cancel/source drift имеют отдельные фактические исходы.
- Проверена совместимость с предоставляющими и потребляющими пакетами.
- Каждый незакрытый source criterion сохранён с owner и next evidence; package validation не считается runtime test.

Полные исходные criteria задач (сопоставить каждый, не объявлять broad task закрытой узким slice):
G3-003 — Скомпилировать проверяемый пакет из существующего snapshot
- Все selected parts имеют hashes/ranges; omitted sources перечислены.

G3-004 — Связать пакет, попытки и журнал без потери provenance
- Один operation ID не принимает другой payload.
- Неопределённый send отличается от failed-before-send и требует reconciliation.
G3-006 — Импортировать типизированный ответ и запрос следующего контекста
- Reply связан с request/packet/target; неизвестные IDs помещаются в review.
- Запрос части разрешается только в выбранном snapshot; ссылка за его пределы не читается.
UI3-003 — Скомпилировать неизменяемый task document с возвратным контрактом
- Каждое требование имеет источник или явно авторство системы.
- Изменение цели/байтов создаёт новую ревизию; старая очередь неизменна.
UI3-004 — Планировать части по ограничениям наблюдаемого UI
- Отклонённая большая часть делится без потери исходного диапазона.
- Никакая очередь не объявляется полной при неотправленных частях.
EVO3-003 — Связать ContextPack с ожидаемым результатом AI
- Manifest включает repo identity, snapshot commit/overlay, chunk hashes, omissions, goal IDs и acceptance version.
- RETURN_CONTRACT требует изменённые пути, критерии, подтверждения и оставшиеся gaps; отсутствие поля не заменяется успехом.
- Изменение manifest создаёт новую revision; receipt относится только к точному digest переданного пакета.
EVO3-006 — Импорт AI claims и артефактов без доверенного исполнения
- Каждый claim ссылается на request ID и criterion; цитата AI доступна без переатрибуции пользователю.
- Команды/инструкции из ответа и исходников хранятся как данные, пока не зарегистрированы точным adapter.
- Повреждённый, частичный или дублирующий ответ не закрывает критерии; все приложения содержат hashes.
EVO3-014 — Точка восстановления и политика данных
- Checkpoint связывает build, data schema, backup manifest и проверяемые hashes; restore rehearsal пройден.
- Политика различает обратимую схему, совместимый rollback и восстановление данных с оценкой последующих записей.
- Отозванная/несовместимая старая сборка не выбирается автоматически; failure plan фиксируется заранее.
TAB4-05 — Документ изменения с происхождением и покрытием
- В документ входят точные goal/scope/criteria, repo SHA, packet SHA, ID частей, связи, известные пробелы и шаблон связанного ответа.
- Полный snapshot и частичный пакет различимы; неприсутствующие части не считаются прочитанными AI.
- Передаваемые группы личных данных соответствуют профилю; невыбранные источники и найденные секреты исключены с видимым отчётом.
- Многочастная передача имеет manifest и продолжение; ограничение размера не приводит к молчаливому обрезанию.
TAB4-19 — Единый пакет для других выбранных AI
- Основной packet/result contract не содержит обязательного Grok-only поля.
- Каждое назначение имеет собственные target binding, profile и квалификацию UI/API; права Grok не переносятся автоматически.
- Различия лимитов, вложений и получения ответа видимы до передачи.
- Ручная загрузка того же проверяемого пакета остаётся доступной при неподдержанном адаптере.
LAYA4-017 — Dedup, версии, tombstones и управляемое хранение
- Exact raw dedup может объединять physical bytes, сохраняя все origin refs и индивидуальные policies.
- Semantic similarity создаёт duplicate candidate; разные решения/версии не сливаются автоматически.
- Current head, deleted/tombstoned и historical versions имеют разные projections.
- Retention/delete распространяется на raw/derived/cache/backups по явному manifest; shared blobs удаляются только при отсутствии допустимых refs.
- Local deletion не заявляет удаление внешней копии; external delivery receipt остаётся объяснимым и минимальным.
LAYA4-018 — Bounded retrieval из архива всей жизни
- Pipeline применяет goal/project/time scope, exact/FTS retrieval, graph neighbours и budget selection перед optional semantic rerank.
- Project/episode/lifetime summaries имеют source refs и expand-to-original; изменение источника помечает summary stale.
- Conflicts, uncertainty и missing facts переносятся в ответ и packet; summary не удаляет альтернативные свидетельства.
- Budget, selected refs и excluded reasons видны пользователю; запрос дополнительных частей ограничен текущим scope.
- Quality evaluation проверяет source recall и evidence correctness, а не только stylistic AI judgement.
LAYA4-019 — Provider-neutral packet и профили Grok/ChatGPT/Gemini
- Core packet содержит goal/scope/criteria/source refs/gaps/result contract независимо от provider UI.
- Provider profile задаёт observed input/attachment limits и version; неизвестный лимит не выдаётся за факт.
- Bytes, exact tokens при наличии qualified tokenizer и token estimate method различаются.
- Передача части не меняет source identity; provider projection имеет собственный digest.
- Carry-over в новую session содержит decisions/open issues/source refs; не утверждает прежнее чтение моделью.
LAYA4-020 — Preview share projection и быстрый локальный экспорт
- Preview показывает goal/source projects/data categories/destination binding revision/parts/bytes/gaps.
- Raw archive и share projection имеют разные IDs; redaction не меняет оригинал и меняет share digest.
- Explicit scope и protected fields проверяются вместе с heuristic scan; heuristic не обещает полного нахождения секретов.
- Смена recipient/account/chat или расширение scope инвалидирует old ready projection, не удаляя локальный archive.
- После одной настройки routine export в прежнем scope не требует повторной настройки; send остаётся отдельным UI adapter эффектом.
LAYA4-021 — Следующие части и bounded запрос missing context
- AI request принимает part/source identifiers из manifest, reason и критерий; произвольный filesystem path не открывается.
- Следующая часть привязана к той же goal/source revision или явно supersedes её.
- Inventory/captured/selected/delivered/model-declared-reviewed/criterion-verified ведутся раздельно.
- Out-of-scope/missing/stale запросы показывают конкретный blocker и не запускают скрытый gather.
- Repeated request возвращает прежний immutable part при совпадающих inputs, не создаёт новую delivery attempt.
LAYA4-025 — Объяснимое «найди нужный контекст для этой цели»
- Каждый factual answer указывает source revision/range или явно unknown; model-generated citation валидируется на существование.
- Панель why-selected показывает exact match/filter/graph/summary reason.
- Запрос дополнительных данных предлагает конкретные missing source categories и ожидаемую пользу для критерия.
- Goal/source conflict не скрывается summary; пользователь может открыть обе версии и изменить scope.
- Ответ сам по себе не вызывает repo execution/provider send и не помечает цель achieved.
LAYA4-027 — Backup, restore и миграции личного каталога
- Backup manifest связывает SQLite snapshot, raw blobs, derived indexes policy, schema versions и hashes.
- Consistent snapshot не смешивает поколения DB/blob publication; backup проверяется до отметки complete.
- Restore сверяет hashes/lineage/tombstones/user labels; никаких stale source resurrection.
- Migration имеет preflight/free-space/rollback point; старый archive читается или даёт явный unsupported schema.
- Restore не восстанавливает grants, credentials или active external sends автоматически; data continuity отделена от execution state.
