Полные исходные criteria задач (сопоставить каждый, не объявлять broad task закрытой узким slice):
UI3-001 — Версия контракта UI-маршрута и связь с существующими owners
- Обязательные поля валидируются; unknown поля не заполняются вымышленными значениями.
- CLI/ACP fallback невозможен без отдельного выбора; V2-035 не является prerequisite.
UI3-002 — Привязать фактический аккаунт, workspace и чат без отправки
- Два чата с одинаковым заголовком различаются либо автоотправка недоступна.
- Смена аккаунта/чата обнаруживается до загрузки и отправки.
UI3-005 — Добавить durable outbox к существующему Core
- Перезапуск восстанавливает очередь без потери ревизии.
- Истёкший lease не превращается в разрешение повторно нажать Send.
UI3-006 — Квалифицировать реальные controls и режим ввода
- Многострочный текст не отправляется при вставке.
- Перемещение фокуса или новый UI contract останавливает дальнейшие внешние действия.
UI3-007 — Собрать локальный и удалённый draft с точной сверкой
- До Send видны назначение, состав и точный prompt.
- Недоступная upload-функция не заменяется передачей одного локального пути в web chat.
UI3-008 — Выполнять scoped auto-send без повторных вопросов
- Одна разрешённая задача отправляется без вопроса на каждую часть.
- Новая область не наследует полномочия из ответа модели или документа.
UI3-009 — Фиксировать отправку по наблюдаемой истории
- Видимый filename не маркируется как remote SHA verification.
- Чужой похожий ответ не принимается за исходящее сообщение задачи.
UI3-010 — Восстанавливать ambiguous send после падения
- Crash сразу после Send не создаёт вторую задачу при повторном старте.
- Несколько совпадений дают конфликт, неполная история — unknown.
UI3-011 — Вести coverage получения и использования частей
- Ответ «всё прочитал» не закрывает все chunk IDs.
- Отсутствующая часть видна и имеет очередь повторной доставки/причину.
UI3-012 — Импортировать результат из связанного UI
- Чужой task ID, незаконченный streaming и неполный JSON не завершают job.
- Повторный импорт того же ответа идемпотентен.
UI3-016 — Независимый от голоса STOP и честное возобновление
- Без ASR STOP работает.
- Локальная остановка не отображается как доказанная отмена удалённой задачи.
UI3-019 — Инвалидировать устаревший UI adapter и восстановить его
- Удалённая кнопка/изменённый composer останавливает отправку до Send.
- После обновления адаптера повторяется затронутая qualification, а не весь бессвязный suite.
PAR3-009 — Сериализация передачи в выбранный UI-чат
- Один owner удерживает chat/composer/clipboard scopes от draft до observed send result.
- Envelope связывает operation ID, target chat, snapshot и content/part hashes.
- Ручной takeover и смена вкладки проверяются до следующего действия.
- Разработка и приёмка адаптера не включают runtime: перед внешним действием проверены activation_prerequisites и актуальные qualified receipts по contracts/ACTIVATION_GATES.json.
PAR3-010 — Сверка неопределённых внешних эффектов
- Timeout после click/send ведёт в effect_unknown, а не в автоматический повтор.
- Повторная доставка job проверяет существующий receipt либо внешний operation ID/content hash.
- Отсутствие способа достоверной сверки сохраняет неопределённость и понятный next action.
PAR3-024 — Продвижение проверенного сценария в повторяемый навык
- Кандидат содержит версии, scopes, inputs/outputs, recovery, evidence и условия инвалидирования.
- Promotion опирается на новые случаи и отказы, а не один успешный прогон.
- Повтор использует прежнее совместимое разрешение без повторных вопросов; новые эффекты требуют отдельного scope решения.
EVO3-004 — Связать наблюдения UI доставки с UpdateCase
- Prepared, attachment_confirmed, message_observed и response_observed различимы; upload не означает прочтение всех частей моделью.
- Receipt хранит target profile/version, chat identity, request ID и наблюдение; новый destination не берёт grant старого чата.
- Unknown после потери связи требует reconciliation; повторное нажатие Send без определения исхода не выполняется.
TAB4-03 — Привязка указанной пользователем вкладки
- Дескриптор содержит роль, origin, доступный устойчивый ID диалога/репозитория, версию привязки и временный указатель на браузер/вкладку.
- Выбор подтверждается видимым превью адресата; одинаковые заголовки вкладок не дают автоматического совпадения.
- Навигация, смена аккаунта, новый диалог в том же tab ID и неоднозначность после перезапуска дают REBIND_REQUIRED.
- Перемещение вкладки не требует нового выбора, если её проверенная идентичность сохранилась.
TAB4-04 — Квалификация адаптера интерфейса Grok Build
- Адаптер сообщает поддержку и ограничения чтения диалога, загрузки файла, проверки черновика, Send и наблюдения результата.
- Версия адаптера связана с наблюдаемым вариантом интерфейса; изменённые ориентиры не приводят к случайному клику.
- Вход выполняет пользователь; истёкшая сессия вызывает состояние NEEDS_LOGIN с сохранением задачи.
- Квалификация не предполагает наличие официального API Grok Build; результат UNSUPPORTED оставляет ручной экспорт доступным.
TAB4-06 — Заполнение проверяемого черновика в выбранном чате
- Перед заполнением проверяются профиль, источник, идентичность вкладки и версия адаптера.
- Вложение связано с локальными именем/размером/document SHA доступным квалифицированным способом; степень подтверждения отражена явно.
- Существующий чужой черновик не затирается; конфликт даёт отдельное состояние и сохраняет исходный документ.
- Автозаполнение заканчивается на DRAFT_ATTACHED; отправка имеет отдельный записанный intent.
TAB4-07 — Отправка с журналом намерения и сверкой неизвестного исхода
- Intent фиксируется до Send и связывает attempt ID, task ID, packet SHA, target binding и profile digest.
- Одна попытка допускает не более одного внешнего действия Send; повтор клиентского запроса возвращает состояние той же попытки.
- Подтверждение содержит наблюдаемый message ID, если доступен, либо ограниченный квалифицированный UI receipt с происхождением.
- Сбой после возможного клика даёт NEEDS_RECONCILIATION; новая отправка запрещена до разрешения исхода.
- OPERATOR_REPORTED и UI_OBSERVED остаются разными типами доказательств.
TAB4-08 — Получение и импорт связанного ответа
- Ответ из выбранного диалога связан с попыткой отправки; требуется точный task ID и packet SHA для импорта.
- Схема ограничена и проверена до записи; команды, новые права и пути из ответа не исполняются.
- Coverage, missing context, findings и ссылки сохраняются с происхождением; DONE остаётся утверждением.
- Повтор старого ответа не откатывает более новую голову результата.
LAYA4-024 — Сохранить повторяемые контекстные automation recipes
- Recipe связывает version, repo alias, data scope, goal template, provider projection и required capabilities.
- Routine повтор внутри согласованного scope идёт без повторных setup вопросов; новые полномочия не выводятся из free-form документа.
- Recipe использует существующие Core jobs/leases/cancel/reconciliation; отдельного worker или бесконечной queue не создаёт.
- Рецепты подготовка/поиск/экспорт квалифицируются до live send/update; реальные UI routes связаны с UI3 receipts.
- Повторный запуск учитывает source change/unknown send и не дублирует внешние эффекты.
ACTION5-23 — Преобразовать показанную автоматизацию в тестируемый skill
- Skill включает только наблюдаемые и разрешённые steps; пароль/secret values заменены credential references.
- Recorded tab/focus координаты не считаются переносимой identity без adapter binding.
- Skill replay проходит sandbox fixture и device scenario с независимым outcome receipt.
- Оптимизация лишних steps сохраняет preconditions, STOP и expected effect invariants.
ACTION5-24 — Инвалидировать skills при drift и permission diff
- Изменившийся adapter/critical permission помечает зависимый skill STALE до execution admission.
- Не затронутые навыки сохраняют valid receipt только при доказанной dependency independence.
- Permission growth отображается как новый scope; прежний grant не расширяется молча.
- Repaired skill имеет новую version; failure capsules не исчезают.
