ПЕРВЫЙ СЛЕДУЮЩИЙ СРЕЗ: LOSSLESS INTAKE → CONTEXT HANDOFF

Цель: в существующем SCE desktop/service слое выбрать локальные источники и репозиторий, ввести задачу и получить источник-связанный контекстный пакет без скрытого усечения; затем импортировать AIResult в ту же задачу.

Сначала выполнить P0: прочитать актуальный repo и его инструкции, зафиксировать base/head и dirty state, найти владельцев store/import/export/tasks. Архивные source snapshots не считать текущим main. Новую независимую БД и второй scheduler не заводить без доказанного архитектурного основания.

Контракт входа: source refs, выбранный snapshot, task, recipient profile, export budget. Контракт выхода: manifest, raw references, readable parts, included/omitted/missing, next-context request template. API budget и память получателя не ограничивают размер сохранённой библиотеки.

Последовательность:
1. Добавить или переиспользовать source/revision/blob inventory и CoverageReport.
2. Подключить chunked export с cursor/checkpoint к существующему service API.
3. Дать desktop-команду «Собрать контекст» и просмотр included/missing/continuation.
4. Импортировать AIResult со связью с task/snapshot. Входной verified_result считать claimed status; локальный verified разрешён только после независимой проверки receipt.
5. Вернуть отчёт о реализации: actual files, tests, receipts, оставшиеся gaps.

Приёмка: >20 документов; полный повторный экспорт; Unicode/длинные пути; один большой файл; повторные версии; повреждённый источник; остановка/возобновление; нехватка места без потери уже сохранённого; контрольный source hash. Тестовое количество — выбранный fixture, не cap продукта. Windows UI проверяется на целевой машине отдельно от Linux unit tests.

Если owner отсутствует, сначала вернуть доказательство поиска и минимальный интеграционный проект. Если нужен дополнительный файл, сформировать NEXT_CONTEXT_REQUEST с точным path/commit/reason. Не объявлять весь исторический ZIP реализованным по закрытию этого среза.

Этот файл описывает будущую задачу. Текущий запрос пользователя разрешает подготовку объединённой R&D-дорожной карты, не запускает реализацию или кампанию автоматически.
