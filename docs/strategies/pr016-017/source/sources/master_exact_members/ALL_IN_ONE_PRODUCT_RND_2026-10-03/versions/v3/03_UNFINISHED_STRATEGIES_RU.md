# Как развиты незавершённые стратегии

## 1. «Сохранить всё» → контракт покрытия

Сущности Source, Revision, Blob, Extraction, Chunk и Coverage связываются устойчивыми ID. Raw bytes неизменяемы; текст, OCR и embeddings — производные с версией инструмента. Покрытие считается отдельно: доступно у источника; получено; извлечено; проиндексировано; реально просмотрено при конкретном ответе. При неподдерживаемом формате blob сохраняется и получает явный статус. Нет лимита «20 документов» или «20 частей»: есть пагинация, checkpoints и ресурсные бюджеты, которые не скрывают необработанный остаток.

Следующий опыт: набор файлов с Unicode, вложенными ZIP, дублями, изменёнными версиями и искусственным прерыванием. Сравнить manifest до/после продолжения. Нулевая потеря полученных байтов — необходимое условие; это не доказательство получения всех удалённых чатов.

## 2. «Идеальные теги и вся история целей» → проверяемый граф

Теги разбить на source/project/entity/topic, intent/goal/task, status/evidence, time/version, sensitivity/access. Метка сохраняет автора, метод и исходный span; пользовательская метка не перезаписывается моделью молча. Goal связан с exact quote, решениями, задачами и receipts. Противоречащие цели сохраняются с временной последовательностью; поздняя версия не удаляет историю.

Следующий опыт: вручную разметить небольшой эталон из реальных разрешённых источников, измерить precision/recall отдельно для goal, task и accepted decision. Ошибочно приписанная пользователю идея — отдельный дефект. История не восстанавливается из summary как дословный transcript.

## 3. «Любой контекст для любого AI» → компилятор handoff

Request содержит цель, snapshot, получателя и бюджет. Retrieval идёт по символам, тексту, графу зависимостей и прошлым результатам. ContextPack содержит обязательные источники, противоречия, missing_sources, omitted_due_to_budget и continuation. Полный archive хранится локально; prompt содержит релевантное представление. Выбор бюджета не уменьшает сохранённый corpus. AI возвращает Result или точный NextContextRequest.

Следующий опыт: 10 задач по двум repo, ручной baseline против компилятора; считать корректность источников, дополнительные запросы и время до пригодного изменения. Отправка в API/веб-интерфейс — отдельная capability выбранного адаптера, не обещание совместимости любого сервиса.

## 4. «AI сам обновляет приложение» → release pipeline

AI формирует patch к конкретному base commit. Тесты проверяют новые контракты, совместимость data migrations и существующие сценарии. Результат проходит review согласно текущим полномочиям пользователя; далее release manifest связывает версии кода, данных и capability contracts. Обновление получает staging, проверку целостности, пробный запуск и rollback. Установленный код не увеличивает доступы автоматически.

Следующий опыт: сломанное обновление на тестовой копии библиотеки, сбой посередине миграции, возврат предыдущей версии без потери пользовательских данных. Git worktree разделяет деревья кода; исполнение недоверенного кода требует отдельной изоляции.

## 5. «Laya автоматизирует всё» → заменяемый router

Сравнить deterministic rules, выбранную версию малого router и более сильный planner на одном RU/EN наборе. Router выдаёт Command IR; capability registry, права и verifier остаются в приложении. Laya — кандидат адаптера, а сохранённые JSON — проектируемый внутренний формат, пока не проверен нативный импорт. Сбой или отсутствие модели не блокируют чтение библиотеки и ручной handoff.

Следующий опыт: held-out команды, перефразировки, неоднозначные имена, шумная транскрипция; измерить ошибки dispatch и abstention, стоимость и p95 на конкретном Dell. Уверенность модели сама по себе не критерий права на действие.

## 6. «Параллельно быстрее» → граф ресурсов и независимые основания

Отдельные collectors могут одновременно записывать наблюдения append-only; альтернативные патчи создаются в worktrees. Ограничения назначаются на account/operation, файл, branch, DB transaction, UI focus и другие конфликтующие ресурсы. У одного логического внешнего действия один operation ID; повтор после сбоя использует прежний ID. При неизвестном результате выполняется reconciliation.

Сначала измеряется последовательный маршрут. Затем сравниваются два независимых маршрута и delayed backup. Оценка учитывает все ветки, отмену, стоимость и общие зависимости доказательств. Три пересказа одного документа не становятся тремя подтверждениями. В SQLite WAL параллельное чтение и запись возможны, но одновременно пишет одна транзакция; это ограничение DB не означает глобальный запрет нескольких producers [S1].

## 7. «Голос управляет ПК» → тот же контракт плюс доступность

Первый интерфейс — push-to-talk/горячая клавиша, видимый transcript и возможность исправления. Далее voice profiles, wake word как отдельный опыт, streaming и альтернативный keyboard/switch input. Для действия выбирается доступный API, CLI, DOM или Windows UI Automation; screen coordinates оставляются отдельным менее устойчивым маршрутом. UIA применима к доступным контролам и требует проверки конкретного приложения [S2].

Проверить ошибочные имена файлов, смену фокуса, пропажу окна, повтор команды, локальный STOP и возобновление. Задержка и доступность измеряются вместе: быстрый неверный клик не успех.

## 8. «24/7 R&D» → устойчивые задания с ценой результата

Schedule создаёт job с checkpoint, входным snapshot, бюджетом, deadline и completion predicate. После рестарта scheduler восстанавливает статус. Failure capsule содержит входы, попытку, ошибку и условия безопасного повторения. Суточный отчёт показывает запланированное и фактически наблюдавшееся время, пропуски, цену и следующий опыт. Эта работа создаёт спецификацию кампании; сама кампания здесь не запущена.

## 9. «Все возможности флешлоанов» → общий экспериментальный стенд

Разделить shared feed, immutable market snapshots, detector candidates, route assembly, simulation, qualification и live authority. Стратегии сравнивать после fees, priority costs, slippage, stale data, contention и failures. Cross-chain/basis/funding не сводить к атомарному same-chain flashloan. Параллельное наблюдение не доказывает способность безопасно посылать параллельные транзакции.

Следующий опыт — существующий sender-free/replay vertical на фиксированном snapshot с явно заданным ожидаемым результатом. Реальный endpoint, протокол, budget и допуски выясняются в P0/P6. Никакой источник в этом архиве не подтверждает текущую прибыльность или live-ready статус.

## 10. «Самообучающиеся навыки» → переносимый проверяемый рецепт

Успешное исполнение создаёт кандидата навыка: параметры, входные версии, требуемые доступы, действия, verifier и область применимости. Навык проверяется на новых примерах, устаревающие зависимости инвалидируют его. Неудачи сохраняются для исключения повторного исследования. Публичная витрина/маркетплейс остаётся отдельной поздней веткой и использует обезличенные демонстрации.
