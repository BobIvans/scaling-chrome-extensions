Приёмка:

- Disconnect не теряет job identity
- Cancel не оживает после restart
- Повтор START не создаёт второй job
- Inventory/capture используют владельцев №1/4
- Повтор/restart/cancel/source drift имеют отдельные фактические исходы.
- Проверена совместимость с предоставляющими и потребляющими пакетами.
- Каждый незакрытый source criterion сохранён с owner и next evidence; package validation не считается runtime test.

EVO3-010 — Граф устаревания evidence и избирательная повторная проверка

TAB4-18 — Delta-контекст LAYA после изменения репозитория
- Части имеют стабильный логический ID и версию из исходных байтов; изменённые файлы не оставляют старые ссылки как актуальные.

LAYA4-002 — Одна кнопка продолжает scan всего выбранного HEAD
- Один start intent фиксирует repo/profile/HEAD; UI последовательно вызывает bounded scan_page до terminal state.
- Double click и network timeout не создают новый snapshot/run intent; перезапуск продолжает сохранённый cursor.
- Экран показывает total/accounted/pending/errors/excluded; progress и Pause/Continue/Stop доступны с клавиатуры.
- Изменение HEAD или revoked profile сохраняет SOURCE_DRIFT/BLOCKED; разные commits не смешиваются.
- Локальное окно можно закрыть без потери ledger; продолжение не требует повторного чтения уже committed pages.
LAYA4-003 — Масштабировать inventory без скрытого усечения
- Текущий предел остаётся явной ошибкой, пока streaming reader не прошёл отдельную квалификацию.
- Streaming Git enumeration сохраняет NUL-safe пути, mode/OID/size и exact HEAD; частичный inventory не публикуется COMPLETE.
- Поток имеет bounded buffer, timeout, stderr budget и temp-stage до atomic publish; subprocess завершён перед restart.
- Неоднозначные/неподдерживаемые paths представлены metadata с причиной и исходным reversible path encoding.
- Cold/warm resource measurements включают большой tree; введён configurable budget вместо безлимитного считывания.
LAYA4-009 — Собрать manifest всего repo и обратный индекс частей
- REPO_MANIFEST содержит все tracked entries, включая errors/exclusions; accounted равен pinned inventory total.
- PARTS_INDEX хранит hashes/bytes/ranges/dependencies и позволяет из части перейти к исходнику и обратно.
- Batch identity включает snapshot, goal revision, grouping/parser versions и export policy.
- Каждая текстовая omission имеет reason: budget/unsupported/protected/missing/selected_out; их нельзя превратить в read coverage.
- Manifest validation не требует размещения всех data bytes в одном native response; текущие transport limits сохраняются.
LAYA4-010 — Сделать resumable сборку ZIP и offline index
- Part publication atomic: staged bytes проверены, затем manifest head указывает на finished part.
- Resume повторно проверяет hashes завершённых parts и не генерирует дубликаты при replay.
- Количество частей определяется размером/бюджетом, фиксированного потолка 20/39 частей нет.
- Offline index открывает цель, группы, gaps, source paths и relative part references; portable ZIP не зависит от абсолютного пути машины.
- ZIP manifest перечисляет каждый output; archive checksum и reconstruction report сохраняются отдельно от утверждений AI.
LAYA4-011 — Инвалидировать только затронутые sources и evidence
- Изменение bytes/parser/resolver/policy учитывается отдельными input hashes; старые results не объявляются current.
- Добавления/удаления/rename сохраняют lineage; old path identity не переписывается задним числом.
- Affected dependents строятся по доказанным edges; unresolved dynamic relations добавляют uncertainty.
- Packets и criterion evidence показывают STALE/RECHECK_REQUIRED с конкретным changed input.
- Clean rebuild и incremental rebuild дают эквивалентный семантический graph/manifest для одинакового source snapshot.
LAYA4-012 — Переиспользовать immutable blobs и ограничить RAM
- Parse cache keyed by raw hash/parser version/resolver config/extraction policy; отсутствие ключа запрещает reuse.
- Один DB writer; read workers ограничены memory/CPU admission, не самостоятельными schedulers.
- Новые cache links не дублируют raw blob; cache eviction удаляет derived data, не origin evidence.
- UI paginated; backlog fragments и hot cache bounded; весь archive не загружается в память.
- Current Core max_parallel=1 не ослаблен; parser parallel extension имеет отдельный measured gate.
